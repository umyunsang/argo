# ARGO — 주장을 스스로 잠그는 연구 에이전트 (1쪽)

## 문제

연구 에이전트는 코드를 잘 돌린다. 문제는 **보고**다.
에이전트가 내놓은 숫자가 실제 실행에서 나온 것인지, 문맥 압축 과정에서 표류한 것인지,
아예 그럴듯하게 지어낸 것인지 **보고서만 보고는 구별할 수 없다.**

이 프로젝트는 그 실패를 실제로 겪었다. 개발 중 한 벤치마크가 모델 호출 0건의 시뮬레이션이었는데
원고·그래프·원장까지 "실행 결과"로 전파됐다. 사후에 검증기를 실제로 돌려보니
정답이 조작된 수치와 **정반대**였다. 지어낸 숫자는 근거가 없을 뿐 아니라 틀렸다.

## 해법 — 책임 가능 복합 하네스

숫자의 **일치**가 아니라 **출처**를 검사한다. 다섯 성분을 모델 주위에 두른다.

1. **타입 컨텍스트 그래프** — 연구 상태를 참고문헌이 아니라 작업 상태로 둔다. 답이 나온 노드는 불변이다.
2. **6필드 결정 프로토콜 + 청구 잠금** — 보고서의 모든 수치를 실행 receipt와 대조하고, 못 맞춘 것을 이름으로 지목한다.
3. **페일클로즈드 수명주기 게이트** — 게이트를 통과해야 결과로 인정한다. 출처 필드가 없는 receipt는 통과하지 못한다.
4. **결과 주도 검색** — 고정 질의가 아니라 현재 결과 상태의 함수로 다시 검색한다.
5. **반증 루프** — 임계값을 미리 등록하고, 어긋나면 방향을 바꾼다. 반복 예산이 끝나면 미해결로 보고한다.

## 7개 벤치마킹 재료의 역할

| 재료 | 메커니즘 | 아암 |
|---|---|---|
| 최소 도구 하네스 | 4개 원시 도구, 무상태 | B0 |
| 영속 REPL·재귀 하네스 | 중간 상태 보존, 서브콜 | B1 |
| 페일클로즈드 수명주기 | 불변 실험 노드, 고정 실행 계약 | B2 (절제 B2−P) |
| 결과 주도 의미 검색 | 상태 의존 재질의 | B2 (절제 B2−R) |
| 타입 컨텍스트 그래프 | 연구 객체 타입·관계 어휘 | B2 (절제 B2−G) |
| 루프 엔지니어링 | 예산·정지 규칙·반증 트리거 | B2 (절제 B2−L) |
| 그래프 엔지니어링 | 스키마·불변성·갱신 정책 | B2 (절제 B2−G) |

학술 근거: 이 세 용어(하네스/루프/그래프 엔지니어링)는 조사 문헌에서 `Loop(LLM + Harness)`로 형식화돼 있다 [2608.21156].

## 근거 상태 — 정직하게

**Study B 사전등록 완료, 미실행.** 아암 7개·과제 3종·검증기·격리 증명·실패 우선 테스트(19+15건)까지 구축했고,
1차 endpoint(McNemar)와 검출 한계(과제당 40쌍에서 절대 통과율 차 0.20~0.28)를 결과 이전에 공개했다.
**아직 어떤 효능 수치도 없다.** 실행은 예산 승인 후다. 이 문서에는 실행되지 않은 숫자를 적지 않는다.
