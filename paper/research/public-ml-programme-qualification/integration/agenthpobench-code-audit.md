## Direct answer

No existing AgentHPOBench adapter qualifies as an actual ML-research P0. The released protocol is a finite hyperparameter menu. Its strict runner gives the decision process prior test results across five interventions and then mechanically chooses the best test-scored trial. It has no independent hidden scorer and no single agent-selected frozen ML artifact. [E04, E06–E09]

`tabm_california_rmse` is the preferred **source task**, not an admitted protocol. It could plausibly become a coherent P0 without changing its core dataset, target, seed-1 split algorithm, target units, or raw RMSE. A separate task-bound apparatus would have to replace only the research and scoring boundary: allow code-level method hypotheses, return development feedback only, lock one prediction table, and let an immutable external scorer compute hidden RMSE once. This conditional path remains unverified. [E11–E14]

Actual P0 is not admitted. Current authority allows apparatus code and local static mocks, keeps native changes prohibited, and does not authorize a specific scientific run. The task contract separately requires one agent-selected frozen artifact before hidden scoring and forbids archive-best substitution. [E02, E03]

### Shortlist exclusion check

Small-looking tasks were not accepted merely because they run cheaply. Metadata calls `align_anything_ragen_bandit` a “generated deterministic multi-armed bandit,” `art_2048_win_rate` a heuristic-policy tuning task, and the xLSTM parity task a 120-step vanilla-backend substitute after the official CUDA kernel failed. They are poor evidence for a real source-task P0 without deeper task-specific justification. [E23]

## Why the shipped protocol fails P0

1. **It is HPO, not an open scientific programme.** Candidate actions are clamped to enumerated `NEW_CONFIG` values. “Wide” and “narrow” variants still only transform those menus. [E04, E09, E11, E15, E19]
2. **Test feedback is adaptive.** The three task prompts include prior `test_*` metrics. The strict runner repeats five interventions. [E06, E14, E18, E22]
3. **Selection agency is wrong.** The strict runner sorts interventions by reported metric and records archive-best as the final configuration. This is exactly the forbidden archive-best estimand. [E03, E06]
4. **Scoring is not independent.** The strict runner imports the task module; each task evaluator reads hidden-candidate labels, trains, computes test metrics, and emits them to JSON in the same boundary. [E07, E13, E17, E21]
5. **There is no ML artifact lock.** Task outputs are metrics JSON. The integrity layer’s “artifacts” are model-response and error files, not a checkpoint or prediction artifact. [E08, E13, E17, E21]
6. **Metric gaming is easy.** Repeated test tuning and archive-best are direct channels. TabM also tells the agent an official winning-like recipe. If solution code becomes editable while the runner trusts `results.json`, it can forge the score. [E06, E14]
7. **Provenance is incomplete.** The repository intentionally omits upstream trees, datasets and weights. Task scripts only check pre-staged data. Base dependencies are loose minimums; task dependencies are delegated to upstream instructions and a machine-specific Conda environment. [E05, E10, E12, E16, E20]
8. **Runtime claims are not measurements.** Epoch/batch/device values are source declarations. No clean install, task run, replay, wall-time, RAM, VRAM, or variance observation was made in this lane.

## Preferred conditional P0 shape: TabM California

This is a qualification target, not an implementation or execution approval.

- Preserve `California Housing`, seed-1 membership generation, 64/16/20 proportions, target scaling/units, and raw RMSE.
- Give all arms the same editable `solution/` boundary. Permit method-level changes in preprocessing, architecture, loss, optimization, and ensembling. Do not give them a finite answer menu.
- Require hypothesis → change → development result → next-decision lineage. Historical paper anchors can be contextual prior evidence, never the primary scorer.
- Expose train/dev labels and hidden features only. Do not mount the complete original table or hidden labels. Disable network and record custody because the source data is public and otherwise reconstructible.
- Before the deadline, the agent selects one `predictions.csv` with immutable hidden row IDs and one finite prediction per row. Hash and timestamp it. Reject later byte changes.
- The scorer lives outside the editable workspace. It validates IDs/order/shape/finiteness and computes `sqrt(mean((prediction - hidden_target)^2))` exactly once from the locked bytes. It ignores `results.json` and never imports agent code.
- Preregister no-lock, malformed artifact, scorer failure, fallback, retry/repair, missingness, MUE, cost, and census handling. Use raw RMSE as primary; do not use paper-anchor normalized improvement or archive-best.
- Treat this task/source/data family as P0 development ancestry and exclude it from later confirmation, as required by the current contract.

This boundary changes the **apparatus**, not the core task. It still needs license/data/dependency receipts, measured compute, deterministic replay, adversarial scorer fixtures, task-bound independent review, and exact user execution approval before P0.

## License, credentials, weights, and compute

- AgentHPOBench declares Apache License 2.0. That license does not close any upstream code, dataset, or transitive dependency license. The repository itself says those remain under their original terms. [E05]
- None of the three inspected task evaluators calls a training API or loads pretrained task weights. The current AgentHPO agent runners separately default to local Qwen3-32B weights, and the strict wrapper defaults to Qwen3-8B/CUDA. Prime could replace that decision backend, but this was not run. [E25]
- The data scripts do not request credentials, but they also do not actually acquire or hash the data. “Account-free” remains unverified for the exact bytes/terms.
- No evidence proves that a large GPU is required for these task models. No evidence proves small-compute feasibility either. TabM/VBLL have CPU fallback code; SparseTSF’s supplied shell path selects CUDA. All performance and resource values are `NOT_OBSERVED`.

## Required closures before an actual P0 request

1. Acquire candidate source/data under a reviewed license chain; record URLs, revisions, byte hashes, terms, and ancestry.
2. Freeze one reproducible environment and command. Measure clean-install success, wall time, RAM/VRAM, and score replay tolerance on the available compute.
3. Freeze train/dev/hidden membership and custody. The agent must not receive hidden labels, the full reconstructible source table, or a bypass path.
4. Use public/dev outcomes only for research decisions. Keep hidden score unavailable until after exactly one eligible artifact is locked.
5. Define the sole artifact schema, ID/order/finite-value validation, hash+timestamp lock, no-lock/fallback rule, mutation rejection and one scorer call.
6. Keep scorer code/data outside the editable arm workspace. Score only artifact bytes; ignore any agent-authored results.json.
7. Replace the fixed menu with an arm-common editable solution layer, while freezing dataset, split algorithm, metric, budget and allowed dependencies.
8. Preregister raw task metric as primary; do not use archive-best or the paper-anchor normalized score as primary.
9. Close invalid/missing/retry/repair/no-replacement, MUE, latency/gate/R2 census and P0 development-ancestry requirements from the current contract.
10. Obtain independent task-bound protocol review and exact user execution approval. Apparatus authorization is not P0 execution authority.
