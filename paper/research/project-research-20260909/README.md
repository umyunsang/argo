# 검증된 결론까지 이어지는 프로젝트 연구

2026-09-09 사용자 실행 계획을 구현하는 현행 연구 경로다. 이전 `study-design-20260909`의 고정 모델·20개 표형 과제 설계는 보존 자료다. Native ARGO 건설 중지는 유지한다. 원고에는 검증된 학술 근거·방법·결과만 옮기며 내부 제품·행사 계획을 기여로 쓰지 않는다.

연구 단위는 하나의 일관된 프로젝트이며, 질문 구체화·문헌·가설·실험·반증·연구용 도구 개선을 에이전트가 수행한다. PI는 임무·제약·완결 기준과 최종 판정을 맡는다. 프론티어 모델 가중치는 학습하지 않는다. 주 결과는 자원 내 PI가 인정한 연구 완결 여부이며, AAA·성능 우위·PI 완료는 각각 기록한다.

## 구현과 현재 근거

## 비교와 검수

B는 지속 실행·문맥·위임·도구 작성·모델 선택을 자유롭게 쓰는 강한 기본 하네스다. B가 자발적으로 P와 유사한 전략을 택하는 것을 막지 않는다. H는 Harness-of-Harness의 고정 역할·근거 전달을 공통 환경으로 옮긴 조건이다. 자율 모델 선택을 허용하므로 원문의 고정 모델 정책과 다른 **운영 방법 재구성**이며 정확한 원형 재현으로 부르지 않는다. P는 부족한 근거에 따른 분기, 다른 기제의 독립 두 팀, 새 세션 블라인드 감독, AAA 수정 루프, 모델 선택과 연구용 도구 개선을 연결한다.

각 팀의 연구·문헌, 실험·구현, 재현·반증은 별도 세션과 작업 공간을 사용한다. 판정 전 상대 결과 접근을 차단한다. 감독은 후보 순서를 무작위화한 익명 패킷만 받고 이전 점수·팀·모델·작성자는 받지 않는다. 방법 자체에서 출처를 추정할 가능성은 남으므로 완전한 오류 독립성을 주장하지 않는다. 실제 역할 집행과 입력 격리는 컨트롤러 실행 근거로 검증한다. 정책 프롬프트만으로 구현 완료를 선언하지 않는다.

AAA는 정확성, 재현성, 연구 논리, 반증·비교, 근거·회계, 주장 범위의 여섯 조건을 모두 만족해야 한다. 미해결 Critical/Major가 있으면 불합격이다. 지적에는 근거 위치·영향·최소 수정·재검증을 붙이고 워커는 수정 또는 근거 있는 반론을 낸다. 문체 취향·근거 없는 비평으로 반복을 무기한 늘리지 않는다. 채택 후보 AAA 뒤에는 해당 루프를 닫고 동결한다. 탈락·실패·미도달 기록도 보존한다.

연구 수행층 검수와 평가 대상 하네스 내부 검수는 `layer`로 분리한다. 수행층 수리로 과거 실패를 성공으로 바꾸지 않는다. 수정은 새 버전·새 실행이다. 최종 평가 후 같은 후보를 계속 튜닝하지 않으며 후속 변경에는 처음부터 별도 보관한 자료를 쓴다.

## 분야와 평가

- Wine Quality: 적·백포도주와 동일가중 MAE. 색상·목표를 제외한 11개 입력의 중복 그룹을 train/dev/final/future 사이에 격리한다. 독립 재학습·재채점과 적용 범위를 확인한다. 충분히 검증된 부정적 결론도 허용한다.
- DuckDB: 실제 `dbgen`의 매개변수화 Q1 파생 질의. 연결·준비·물질화·실행·정리 총비용과 답의 동등성을 측정한다. 20회 이상 무작위 순서의 대응 측정, 독립 반복, 새로운 매개변수에서 최소10% 개선을 확인한다. 정밀도가 부족하면 미확정이다. 공식 TPC 성능으로 표시하지 않는다.
- 이방성 확산: PyAMG 생성 선형계의 알려진 해, 독립 stencil 잔차·해 오차, setup/solve 비용과 유효 범위를 확인한다. 유리한 조건이 없다는 결론도 근거가 충분하면 허용한다. 실제 물리 발견이나 PDE 이산화 정확도로 확대하지 않는다.

최종·후속 평가 자료는 저장소 밖 평가기 영역에 두고 작업 컨테이너에 마운트하지 않는다. 파일 모드나 해시만으로 비노출을 증명하지 않는다. 공개 데이터 재취득 위험과 네트워크·호스트 도구 경계를 함께 검증해야 최종 평가로 인정한다. 개발 설정의 관측은 미공개 최종 설정 결과를 대신하지 않는다.

## 시간·비용과 연속성

실행 재개12시간 이내 실제 기준선·가설 시험, 7일 이내 첫 보고, 이후 연구 근거·초고와 9월 말 시연으로 이어진다. 준비가 지연되면 실행 가능한 작은 실제 문제를 먼저 측정한다. 프로젝트당8시간·8 CPU-core-hours, 연구 컨테이너 합계4 CPU·4.5GiB, 성능 작업은 직렬 실행한다.

추가 과금 총300000원은 첫 주150000원·후속90000원·예비60000원이다. 기존 구독·로컬 계산을 우선하며 팀·감독·검색·실패·재시도도 센다. 미확인 사용량은0이 아니며 미정산 예약과 실패를 보존한다. 자동 증액·주별 초기화는 없다. 모델 풀의 구체 ID와 경로는 비교 시작 전에 공통으로 동결한다. 새 모델은 다음 비교 묶음부터 적용한다.

정상 조건에서도 모델 선택은 자율적이다. 연속성 시험은 첫 가설 관측과 체크포인트 뒤 세션을 중단하고 사용 모델을 금지한다. 새 세션에서 다른 허용 모델로 같은 연구를 잇는다. ORX 진행 중 실행은 ID로 재연결하고 중복 실행하지 않는다. 시점 미도달도 분모에서 제외하지 않는다.

첫 주는 `3분야 × B/P × 정상/연속성`12개 캠페인이다. 후속에는 개발로 선택한 P를 고정하고 B/H/P 정상 비교를 먼저 완료한 뒤 연속성을 추가해 최대18개다. 같은 목표·자료·모델 후보·도구·자원 기회를 제공하며 모델 선택을 포함한 **전체 운영 방법의 효과**로 해석한다. 소수 사례 차이로 일반적 우월성·SOTA를 선언하지 않는다.

## 종료와 후속

최종 시연은 목표→독립 팀→블라인드 비평·수정→모델 교체·복구→검증된 결론과 근거를 보여준다. 기록 재생과 실시간 실행을 명시한다. 우위가 확인되지 않으면 더 단순하고 검증된 구성을 택한다. 예산·시간 한도에서 미달·실패·미확정을 그대로 보고한다. 기존 native 재개 조건과 PI의 명시적 재개 결정은 별도다.
