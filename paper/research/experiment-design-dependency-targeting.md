## 1. 좁힌 연구 질문

> 상속된 연구 상태에서 어떤 근거가 철회·supersede될 때, **그래프에서 기계적으로 계산한 의존 목표**가
> (a) 오라클이 지정한 임계 경로와 같은 집합을 만들고,
> (b) coarse·캐스케이드 방식의 과/미무효화를 피하며,
> (c) 동일 검증 예산에서 결정 충분성까지 이어지는가?

`(a)`,`(b)`는 프로토콜 속성이므로 모델 호출 없이 결정론적으로 측정한다(Stage A).
`(c)`는 모델 속성이므로 별도 승인된 유과금 단계에서만 측정한다(Stage B).

## 2. 가설

- **H1 (targeting fidelity).** 지배 기반 목표 `T_intent(e,G)=reach(G)∖reach(G∖{e})`를 계산하는 정책은
  독립 지지(다중 부모)와 다중 간선 이벤트를 포함한 그래프군에서 오라클 목표와 **over=0, under=0**으로 일치한다.
- **H2 (cascade over-revocation).** 전방 도달성 캐스케이드는 독립 지지가 존재하는 그래프에서 **over>0**을 낸다.
- **H3 (coarse harm).** 범위 전체 초기화는 무효화 대상이 아닌 유효 결과까지 폐기해 보존율을 떨어뜨린다.
- **H4 (no-op under-revocation).** 무효화를 하지 않는 정책은 **under>0**을 낸다.
- **H5 (batch non-composition).** 다중 간선 이벤트에서 간선별 목표의 합집합은 결합 목표와 다를 수 있다.
- **H6 (Stage B, 미승인).** 계산 목표를 예산 안에서 우선 제시하면 stale-consistent 결정 비율이
  `2608.25553`이 보고한 오라클 개입 효과의 일부를 재현한다. **현재 미검정.**

H1–H5는 무과금·결정론이다. H6은 유과금이며 정확한 총비용 승인 전에는 실행하지 않는다.

## 3. 조건(arm)과 고정 표면

모든 arm은 동일한 그래프 인스턴스, 동일한 이벤트, 동일한 관측 가능 정보를 받는다. 유일한 차이는 **목표 계산 정책**이다.

| arm | 정책 | 문헌 대응 |
|---|---|---|
| `P0_NONE` | 아무것도 무효화하지 않음 | naive memory(A1) `2609.00243` |
| `P1_COARSE` | 이벤트가 닿은 범위 전체를 무효화 | table-level invalidation `2609.00243`, deployer revocation `2608.30091` |
| `P2_CASCADE` | 변경 노드에서 전방 도달 전체를 무효화 | tree cascade `2608.30091`, 단순 영향 부분그래프 |
| `P3_DOMINANCE` | 지배 목표 `reach(G)∖reach(G∖E)` | `T_intent` `2608.30091`을 근거 그래프로 이식 |

`P3`이 이 연구의 처리군이고 `P2`가 가장 가까운 강한 비교군이다. `P0`,`P1`은 해석용 하한/상한이다.

## 4. 측정

- `over_revocation = |M ∖ S|`, `under_revocation = |S ∖ M|` (정의 `2608.30091`)
- `exact_target_match` = over=0 ∧ under=0
- `preserved_valid_results` = 이벤트와 무관하게 유효한 결과 중 보존된 수
- `inspection_fraction` = 목표 계산에 실제로 방문한 노드 비율 (BoardroomAI 14.59% 대응)
- 분모 동시 보고: 완료 인스턴스 수. **event-count 지표만 보고하지 않는다** — `2609.00243`이 지적한
  "소진된 실행이 정밀해 보이는" 위험을 막기 위해서다.

## 5. 표본과 추론 단위

- 추론 단위는 **그래프 인스턴스(과제)**다. 인스턴스 내부 반복은 중첩이다.
- Stage A 표본: 사전 고정 seed로 생성한 합성 인스턴스. 계열은 `chain`, `diamond_independent`,
  `shared_result`, `multi_edge_batch`, `unrelated_only`.
- 각 인스턴스는 오라클 목표를 **정의로부터 직접** 계산해 라벨링한다. 라벨 산출은 정책 구현과 분리된 경로다.
- Stage A는 합성이므로 **모집단 일반화를 주장하지 않는다**. `2608.13046`,`2608.25553` 모두 같은 한계를 명시한다.

## 6. 분석과 판정

- H1: `P3`의 exact match 비율이 1.0이어야 한다. 하나라도 불일치면 H1 기각.
- H2–H4: 각 정책의 over/under 분포를 인스턴스 단위로 보고한다. 방향 예측이 어긋나면 해당 가설 기각.
- H5: 배치 이벤트 계열에서 간선별 합집합과 결합 목표가 다른 인스턴스가 존재해야 한다.
- 유의성 검정은 하지 않는다. Stage A는 결정론적 계약 검사이며 표본 추출 불확실성이 없다.
- 모든 실패는 보존한다. `P3`가 어떤 계열에서 지면 그 계열을 그대로 보고한다.

## 7. 반증 조건

- 오라클 라벨이 정책 코드와 같은 함수를 재사용하면 무효다.
- 정책이 이벤트 이후 그래프에서 목표를 계산하면 무효다(사전 그래프에서 계산해야 함, `2609.00243` pre-reload edge walk).
- 어떤 정책이 인스턴스 식별자나 계열 이름을 읽으면 무효다.
- 생성기가 `P3`에 유리한 구조만 만들면 무효다. 그래서 `unrelated_only`와 `chain`을 포함한다.

## 8. 이 결과가 ARGO 설계를 바꾸는 방식

- H1 성립 + H2/H3 확인 → ARGO research-state plane은 **지배 기반 선택적 재개방**을 계약으로 채택한다.
- H1 실패 → 타입드 그래프를 재개방 제어에 쓰지 않고 감사·수출용으로 축소한다.
- H2가 성립하지 않으면(캐스케이드도 정확) 그래프 타입 정보의 근거가 약해지므로 더 단순한 트리를 채택한다.
- Stage B 미실행 상태에서는 어떤 경우에도 **효능·SOTA·일반 성능 주장을 하지 않는다**.

## 9. 비용

Stage A: 모델 호출 0, 지출 $0. Stage B: 미승인, 금액 미산정.
