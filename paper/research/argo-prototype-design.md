# ARGO 프로토타입 설계 — 벤치마킹 기반 설계안

작성 2026-09-04 · 근거 영수증 `paper/research/external-event-facts-receipt.json`

## 1. 설계가 답해야 하는 질문

대회 주제는 "연구의 모든 과정에 AI 에이전트를 심는다"이다. 그러나 연구 과정에 에이전트를 넣는 일과
**그 에이전트가 낸 결과를 믿을 수 있게 만드는 일**은 다른 문제다. 본 설계는 후자를 목표로 잡는다.

근거는 추측이 아니라 본 연구에서 실제로 측정한 것이다.

- 채점 파이프라인이 **근거를 찾지 못한 경우를 음성으로 처리**했을 때, 두 심사 모델이 전체 산출물을
  다시 읽자 음성 판정의 **38.9%가 뒤집혔다.**
- 채점 **방법을 바꾼 것만으로 생긴 변화가, 검출하려던 효과 크기의 2.3배**였다.
- 채점 방법이 만든 분산이 측정 대상 분산의 **1.48배**였고 부호가 뒤집혀 상수 보정이 불가능했다.
- 도구 감사가 렌더러·판독기·색상 검사에서 **조용히 통과하던 결함 3종**을 잡아냈다.

즉 자율 연구 시스템의 실패는 실험을 만들지 못해서가 아니라, **자기 계측기가 틀렸다는 것을 모르는 데서**
온다. ARGO는 이 지점을 설계 목표로 삼는다.

## 2. 벤치마킹 설계 행렬

각 축은 기존 시스템에서 무엇을 가져오고 무엇을 새로 얹는지를 분리해 적는다. 태그는 기여 원장 어휘를
따른다.

| 설계 축 | 벤치마킹 대상 | ARGO가 계승·채택한 것 | ARGO가 더한 것 | 구분 |
|---|---|---|---|---|
| 실행 기반 (execution substrate) | 영속 REPL을 단일 도구로 두는 표현력 하네스 | 코드를 행동으로 삼고 문맥을 변수로 다루는 실행 기반을 계승 | 실행 단위마다 결정 기록 식별자를 붙여 사후에 어떤 판단이 그 실행을 낳았는지 되짚게 한다 | `INHERITED` |
| 상태 지속 (state persistence) | 지속 학습 하네스의 기억·기술·프롬프트·서브에이전트 명세 | 세션을 넘어 살아남는 상태 계층을 계승 | 상태 갱신을 근거 등급과 함께 기록해, 검증되지 않은 학습이 조용히 정책이 되는 것을 막는다 | `MODIFIED` |
| 위임 (delegation) | 재귀적 서브에이전트 | 독립 작업의 병렬 위임을 계승 | 생성자와 평가자를 분리해 같은 에이전트가 자기 산출물을 채점하지 못하게 한다 | `MODIFIED` |
| 실험 생애주기 (experiment lifecycle) | 답이 나온 노드를 불변으로 두고 실행 명령을 고정하는 실험 트리 | 불변 노드와 고정 실행 계약을 계승 | 노드마다 사전등록과 반증 조건을 요구해, 결과를 본 뒤 판정 기준이 바뀌지 못하게 한다 | `MODIFIED` |
| 검색 (retrieval) | 의미 검색과 적응형 검색 증강 | 의미 검색을 근거 수집 경로로 채택 | 검색 재현율을 채점 전에 측정한다. 본 연구에서 근거를 못 찾은 결과를 음성으로 처리했을 때 실제로 오판이 발생했다 | `RE_DERIVED` |
| 지식 표현 (knowledge representation) | 근거 그래프로 실험과 원고를 연결 | 문맥 그래프를 지식 표현으로 채택 | 노드마다 근거 등급과 허용성 판정을 붙이고, 투영 다이제스트로 그래프가 소리 없이 어긋나지 못하게 한다 | `RE_DERIVED` |
| 루프 설계 (loop engineering) | 관찰·추론·행동 루프와 반성 기반 재시도 | 관찰 조건부 절차와 반성 루프를 계승 | 루프의 각 회차가 여섯 필드 결정 기록을 남기고, 반증 조건을 결과 확인 전에 고정한다 | `MODIFIED` |
| 평가 (evaluation) | 하네스 최적화를 모델 강도와 분리하고 보류 집합을 보호하는 평가 | 분리된 평가와 보류 보호를 채택 | 측정 도구 자체를 반증 시험에 건다. 도구 감사가 실제로 세 종류의 결함을 잡아냈다 | `ORIGINAL_ARGO` |

## 3. 설계 원칙 네 가지

1. **판정 기준은 결과보다 먼저 고정된다.** 각 실험 노드는 사전등록과 반증 조건을 함께 갖는다.
2. **계측기도 피험자다.** 측정 도구는 일부러 망가뜨린 입력에서 반드시 실패해야 하며, 실패하지 않는
   도구는 근거를 만들 자격이 없다.
3. **생성자와 평가자는 분리된다.** 같은 에이전트가 자기 산출물을 채점하지 않는다.
4. **근거에는 등급이 있다.** 요약만 읽은 것, 전문을 읽은 것, 직접 실행한 것을 그래프에서 구분한다.

## 5. 반증 조건

이 설계가 틀렸다면 다음이 관측된다.

- 계측기 감사를 붙여도 결함이 나오지 않는다면, 책임 계층은 비용만 늘리는 장치다.
- 결정 기록을 강제해도 사후 기준 변경이 계속 일어난다면, 기록은 형식일 뿐 통제가 아니다.
- 근거 등급을 구분해도 하류 판단이 달라지지 않는다면, 등급은 장식이다.
