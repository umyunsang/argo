## 1. 영역 9: provider·모델 라우팅과 rlm 동적 라우팅

대상 메커니즘: 오케스트레이터 모델이 등록된 provider를 확인하고, 하위 에이전트에 할당할 작업의 크기와 추론 수준에 따라 사용 가능한 모델을 동적으로 라우팅해 배정한다. 이 메커니즘의 각 구성 요소를 발표된 논문으로 근거화한다.

| 하위 주제 | 찾아야 할 것 |
|---|---|
| LLM 라우팅 foundations | 질의별 모델 선택(품질–비용 트레이드오프), 모델 캐스케이드, 라우터 학습, 라우팅 벤치마크 |
| 작업 크기·난이도 추정 | 라우팅 입력이 되는 난이도 예측, 입력 길이·컨텍스트 크기 기준 분할과 배정 |
| 추론 수준과 테스트타임 컴퓨트 할당 | 추론 길이·사고 예산의 적응적 배분, 추론 강도 설정이 정확도·비용에 미치는 효과 |
| 오케스트레이터–하위 에이전트 모델 배정 | 이기종 모델 다중 에이전트, 역할·과제별 모델 할당, 계층적 위임의 비용 효율 |
| provider 레지스트리와 능력 발견 | 다중 provider 게이트웨이, 가용성·비용·지연·능력 기반 선택, 폴백과 장애 처리 |
| rlm 재귀 위임의 동적 라우팅 | 재귀 깊이·부분 문제 크기에 따른 모델 선택(영역 7 rlm 항목과 상호 연결) |

요구 사항은 #0002 §4와 같다: 검색 스트림, context graph 노드, 앵커 논문 3편 이상 FULL_PAPER_READ, 필요성 근거와 설계 선택 근거 구분. pi·prime-agent 공개 출처가 라우팅을 설명하면 #0002a §1의 3분류(자체 출처·개념 원천·대조 하네스)로 함께 기록한다.

## 2. 논문에서의 사용

- Proposed Method: 하네스의 라우팅 정책을 일반 용어(동적 모델 라우팅 정책)로 기술하고 구성 요소마다 영역 9 근거를 단다. 내부 구현의 provider 이름·설정 파일·모델 id는 넣지 않는다. 실험 재현에 필요한 모델 명세는 실험 절에서만 표로 제시한다.
- 연구 설계(#0002c): 라우팅을 가설이나 조건(예: 동적 라우팅 대 고정 모델)으로 채택할지는 세션이 design rationale record로 판단한다. 채택하면 비교 실험 표에 라우팅 벤치마크·캐스케이드 실험을 포함하고 비용·정확도 지표를 함께 정한다. 채택하지 않으면 그 이유도 기록한다.
- 차별화 행렬(#0002a §2)에 "모델 라우팅" 축을 추가한다.
