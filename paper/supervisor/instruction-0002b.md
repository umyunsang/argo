## 1. 영역 8: 자율 연구 엔진 기능 문헌

openresearch cli가 수행하는 기능들을 발표된 논문으로 찾아 논문에 사용한다. 엔진 자체가 아니라 기능 단위로 문헌을 찾는다.

| 하위 주제 | 찾아야 할 것 |
|---|---|
| foundations | 자율 연구·AI 과학자 계열의 기초 논문(가설 생성 → 실험 → 논문화 루프) |
| 문헌 탐색과 전문 읽기 | 논문 검색·선별·전문 읽기 수준 구분, 인용 검증, 허위 인용 탐지 |
| 근거 원장 (claim–evidence) | 주장과 근거를 묶어 추적하는 구조, 근거 수준 표기, 재검토 |
| 사전등록과 결정론적 검증 | 사전등록, 프로토콜 지문, 재현성 검증, fail-closed 파이프라인 |
| 실험 실행과 실행 추적 | ML 실험을 수행·기록하는 에이전트, run 단위 추적, 벤치마크 |
| 반복 연구 루프 | 결과를 보고 다음 실험을 정하는 에이전트 루프, 중단 규칙 |
| 논문 작성과 검토 | 초안 생성, 설문 자동화, 에이전트 심사 |

요구 사항은 #0002 §4와 같다: 검색 스트림, context graph 노드, 앵커 논문 3편 이상 FULL_PAPER_READ, 필요성 근거와 설계 선택 근거 구분. 영역 5(RAG engine)의 retrieval pipeline과 겹치는 논문은 양쪽에 연결한다. openresearch 자체의 논문·기술 보고서가 있으면 evidence matrix에는 기록하되 논문 본문과 참고문헌에는 넣지 않는다(§2).

## 2. 명칭 금지 (hard)

작성할 논문 어디에도 다음 토큰이 나타나면 안 된다: `openresearch`, `OpenResearch`, `open-research`, `orx`, `.orx`, orx run id, `migration-state`, `oracle contract`, `supervisor`, 인스턴스 회사명·도메인. 본문, 참고문헌, 그림·표 캡션, 부록, 국문요약, 키워드 모두 해당한다.

- 엔진을 가리켜야 할 때는 일반 용어 하나를 정해 일관되게 쓴다(예: "자율 연구 엔진(autonomous research engine)"). 엔진을 참고문헌으로 인용하지 않는다. 엔진의 기능은 영역 8 논문으로 근거를 댄다.
- 구현 기반 문장은 "공개된 에이전트 파운데이션[pi·prime-agent 발표 출처 인용] 위에 자율 연구 엔진을 참조 구현했다" 수준으로 고친다. pi·prime-agent 명칭은 #0002 §3의 인용 형태로만 허용한다.
- 위 토큰 검사를 논문 검증 파이프라인에 결정론적 게이트로 추가한다. paper.tex, .bib, 그림 소스, 생성된 PDF 텍스트를 검사하고 하나라도 발견되면 빌드를 실패시킨다. 게이트 추가는 decision record와 체크포인트 커밋으로 남긴다.
- 현재 paper.tex·bib·ledger에서 위 토큰이 나타나는 위치를 먼저 목록화하고 #0002 §6 1단계(금지 항목 제거 계획)에 합친다.
