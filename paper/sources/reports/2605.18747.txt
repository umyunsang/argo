## Detailed Report: Code as Agent Harness

### 1. Authors and Institution(s)

The research paper "Code as Agent Harness" is authored by a large collaborative group from multiple institutions. The core contributors and corresponding authors include Xuying Ning, Katherine Tieu, Dongqi Fu, Tianxin Wei, Zihao Li, and Yuanchen Bei.

The affiliations of the authors span:
*   University of Illinois Urbana-Champaign (1)
*   Meta (2)
*   Stanford University (3)

### 2. How This Work Fits into the Broader Research Landscape

The work addresses a shift in the role of code within the evolving landscape of large language model (LLM)-based agentic systems. Traditionally, code has been viewed primarily as an output target for LLMs, demonstrating their capability in generating functional programs for tasks like competitive programming or software engineering. This paper repositions code as an "operational substrate" that underpins various facets of agent intelligence, including reasoning, action, environment modeling, and execution-based verification.

The concept of an "agent harness" has been discussed in prior literature, referring to the software layer that augments an LLM with tools, memory, sandboxes, and feedback mechanisms to enable persistent task execution. This paper refines this perspective by focusing on "agent-initiated code artifacts"—interactive code objects created, executed, observed, revised, and shared by agents within a task execution loop. It distinguishes these artifacts from both the LLM's internal capabilities and the pre-defined system infrastructure of a harness.

The survey differentiates itself from existing literature reviews that typically treat code as an end product of LLMs. Instead, it centralizes code as the foundation for agent infrastructure, providing a unified view of how code supports reliable, closed-loop agentic behavior across diverse systems. It aims to provide a systematic organization of the research around this "code as agent harness" perspective, spanning its interface, mechanisms, and scaling challenges.

### 3. Key Objectives and Motivation

The primary objective of this work is to formalize and systematically analyze the concept of "code as agent harness." This involves reframing the role of code within LLM-based agentic systems from a mere generated artifact to a foundational operational substrate.

The motivation for this re-framing stems from several observations regarding the expanding capabilities of LLMs and the increasing complexity of tasks undertaken by AI agents:
*   **Expanding Role of Code:** LLMs demonstrate strong capabilities in understanding and generating code. This capability is increasingly being leveraged not just for producing final code, but for supporting agent operations. Programs are used as a medium for reasoning (e.g., externalizing computation), acting (e.g., executable policies for robots or GUI agents), and environment modeling (e.g., representing state, dynamics, and feedback).
*   **Need for Executable and Inspectable Substrate:** Purely textual reasoning or planning in LLMs can be unreliable for symbolic computation, difficult to verify, and unable to persist computational progress across steps. Code, by its nature, is executable, inspectable (exposing intermediate steps), and stateful (representing task progress persistently), offering a solution to these limitations.
*   **System-Level Reliability:** The paper identifies a bottleneck in agent autonomy not only in the base model's reasoning but also in the reliability of the system connecting model outputs to long-horizon actions and persistent states. Code as an agent harness aims to address this by providing a robust and verifiable medium for these connections.
*   **Unifying Diverse Approaches:** Various research efforts already utilize code in ways that align with the "agent harness" concept, but a unified conceptual framework is lacking. The paper aims to synthesize these disparate approaches into a coherent taxonomy.

To systematically study this perspective, the work is organized around three connected layers:
1.  **Harness Interface:** How code forms the fundamental connection between an agent and its reasoning, actions, and environment modeling capabilities.
2.  **Harness Mechanisms:** The functions that enable code-harnessed agents to maintain reliability over time, including planning, memory, tool use, feedback-driven control, and optimization.
3.  **Scaling the Harness:** How code artifacts facilitate coordination, review, and verification in multi-agent systems.

By fulfilling these objectives, the paper aims to provide a roadmap towards the development of executable, verifiable, and stateful AI agent systems.

### 4. Methodology and Approach

This paper employs a methodology characteristic of a comprehensive literature survey, focused on conceptual framing and systematic organization of a rapidly evolving research area. The approach involves:

1.  **Conceptual Formalization:** The authors introduce and formalize the "code as agent harness" perspective. This involves distinguishing "agent-initiated code artifacts" from model-internal capabilities and system-provided harness infrastructure, emphasizing code's role as an executable, inspectable, and stateful medium for agent operations.

2.  **Three-Layered Taxonomy:** The core of the approach is a hierarchical taxonomy that organizes existing literature into three interconnected layers, reflecting the progression of code's operational role within an agent loop:
    *   **Harness Interface (Section 2):** This layer examines how code serves as the basic interface between a language model and its task environment. It is subdivided into:
        *   **Code for Reasoning:** How code externalizes internal logic into verifiable computation, allowing external interpreters, solvers, or execution traces to check and refine reasoning.
        *   **Code for Acting:** How generated programs serve as policies, tool calls, or reusable skills for interacting with embodied, GUI, and software environments.
        *   **Code for Environment Modeling:** How program states, repositories, traces, simulators, and tests represent world state, dynamics, and feedback signals for agent interaction.
    *   **Harness Mechanisms (Section 3):** This layer investigates how code-harnessed agents maintain reliability over long-horizon tasks. It covers:
        *   **Planning:** Methods for organizing long-horizon software tasks through decomposition, structural grounding, search, or workflow orchestration.
        *   **Memory and Context Engineering:** Techniques for managing mutable state across long interactions, including working memory, semantic memory, experiential memory, long-term memory, multi-agent memory, and context compaction.
        *   **Tool Use:** How agents connect to governed executable interfaces like APIs, repositories, and verification tools.
        *   **Harness Control (Plan-Execute-Verify Loop):** Reframing debugging as a broader control process that involves contract formation, sandboxed execution, permissioned state transitions, and deterministic verification.
        *   **Agentic Harness Optimization:** How the harness itself can be measured and improved through telemetry, evolution agents, and governed mutations.
    *   **Scaling the Harness (Section 4):** This layer extends the harness concept to multi-agent systems, focusing on how shared code artifacts support coordination, review, and collective verification. It explores:
        *   **Improved Coding Support:** Functional role specialization, diverse interaction modes (e.g., critique, debate), and optimized workflow topologies (e.g., chain, hierarchical, adaptive).
        *   **Execution Feedback and Shared-Harness Synchronization:** Integration of various execution feedback types (compiler errors, test results) and mechanisms for maintaining consistent shared program state (e.g., blackboards, structured context scheduling).
        *   **Position on Shared Code-Centric Substrate:** Proposing a unified view of how the shared program environment is represented and how harness state converges.

3.  **Application Domain Analysis:** The paper connects its taxonomy to five key application domains: coding assistants, GUI/OS agents, embodied agents, scientific discovery, and personalization/recommendation. This demonstrates the practical instantiation of the "code as agent harness" paradigm across diverse real-world settings.

4.  **Identification of Open Challenges:** Finally, the authors outline critical open problems and future research directions for "harness engineering," including evaluation, semantic verification, self-evolving harnesses, transactional state, human oversight, and multimodal integration.

By systematically categorizing existing work and proposing a unified conceptual framework, the paper aims to provide a structured understanding of current progress and future challenges in building robust AI agent systems that leverage code as their foundational infrastructure.

### 5. Main Findings and Results

The paper's main findings and results are presented through its comprehensive taxonomy and the synthesis of representative methods across various domains.

**5.1. Harness Interface: Code for Reasoning, Acting, and Environment Modeling**
*   **Code for Reasoning:** Code serves as an interface for externalizing reasoning, transforming internal model logic into executable and verifiable computation.
    *   **Program-Delegated Reasoning:** LLMs generate programs for external interpreters, improving reliability in tasks requiring symbolic or arithmetic computation (e.g., Program-of-Thoughts, PAL).
    *   **Formal Verification and Symbolic Reasoning Interfaces:** Code or formal languages (e.g., Lean, Isabelle) provide persistent intermediate representations for hybrid neural-symbolic methods, enabling verifiable proof search and structured control (e.g., DeepSeek-Prover, CodeSteer).
    *   **Iterative Code-Grounded Reasoning:** Reasoning is a closed-loop process where execution traces and runtime feedback guide iterative refinement and learning (e.g., NExT, CodePRM, RLEF).
*   **Code for Acting:** Code acts as an action interface, translating high-level intent into grounded, executable operations.
    *   **Grounded Skill Selection:** Agents map language intent to executable behaviors using reusable skill libraries, often considering environmental and physical constraints (e.g., SayCan, KnowNo).
    *   **Programmatic Policy Generation:** Code directly materializes executable policies for controlling robots, GUIs, or software environments, specifying control logic and API interactions (e.g., Code as Policies, RoboCodeX).
    *   **Lifelong Code-Based Agents:** Executable interaction interfaces persist, evolve, and accumulate capabilities over long-horizon interactions, forming reusable skill memories (e.g., Voyager, UI-Voyager).
*   **Code for Environment Modeling:** Code represents the environment itself, enabling agents to explicitly store, inspect, execute, and modify world state.
    *   **Structured World Representations:** Environments are modeled through programmatic structures like class hierarchies, room programs, or renderable HTML, allowing for explicit manipulation and inspection (e.g., ViStruct, Code2World).
    *   **Execution-Trace World Modeling:** Environment dynamics are learned and represented directly from executable interaction traces, enabling predictive models of future states (e.g., Code World Model, WorldCoder).
    *   **Code-Grounded Evaluation Environments:** Executable systems (e.g., sandboxes, unit tests, simulators) serve as objective interfaces for measuring agent behavior and interaction quality (e.g., SWE-bench, AgentBench, InterCode).
    *   **Verifiable Environment Construction:** Environments are programmatically synthesized, scaled, and validated as harness artifacts, defining state transitions, tool affordances, and verifiers (e.g., SWE-smith, EnvScaler).

**5.2. Harness Mechanisms: Planning, Memory, Tool Use, Control, and Optimization**
*   **Planning for Agent Harness:** Planning acts as a harness control layer, structuring how agents externalize intent into executable steps and regulate reasoning trajectories.
    *   **Linear Decomposition, Structure-Grounded, Search-Based, Orchestration-Based:** These paradigms range from sequential step generation (Self-Planning) to grounding in explicit task structures (CodePlan), exploring multiple solution paths (CodeTree), and coordinating specialized agent roles (MapCoder).
*   **Memory and Context Engineering:** Manages the tension between limited context windows and continuously expanding task states.
    *   **Working, Semantic, Experiential, Long-Term, Multi-Agent Memory:** Different memory types support current task trajectory, retrieve repository evidence, store reusable experiences, preserve validated knowledge, and synchronize shared state across agents.
    *   **Context Compaction and State Offloading:** Mechanisms to manage context by summarizing information and offloading full-fidelity artifacts to external storage.
*   **Tool Use for Agent Harness:** Tools form the action and observation layer, expanding agent capabilities and exposing feedback.
    *   **Function-Oriented, Environment-Interaction, Verification-Driven, Workflow-Orchestration:** Tools enable API calls, interaction with development environments, post-generation verification, and coordination of complex workflows.
*   **Harness Control (Plan-Execute-Verify Loop):** Transforms debugging into a control process for state transitions.
    *   **Planning as Contract Formation, Sandboxed Execution, Permissioned State Transition, Deterministic Verification:** Plans define intended changes, executed in isolated environments with access controls, and verified by objective sensors (linters, tests).
*   **Agentic Harness Engineering:** The harness itself is an object of analysis and optimization.
    *   **Deep Telemetry, Evolution Agent, Governed Harness Mutation:** Structured traces diagnose failures, a meta-agent proposes and evaluates harness revisions, and changes are governed like safety-critical code.

**5.3. Scaling the Harness: Multi-Agent Orchestration over Code**
*   **Improved Coding Support through Multi-agent Collaboration:** Multi-agent systems address single-agent limitations by distributing responsibilities.
    *   **Functional Role Specialization:** Agents adopt roles like programmer, tester, reviewer, and architect (e.g., ChatDev, MetaGPT, AgentCoder).
    *   **Diverse Interaction Modes:** Communication is mediated by artifacts, including collaborative synthesis, critique and repair, adversarial validation, and reasoning debate.
    *   **Optimized Workflow Topology:** Interaction structures range from predefined chains (waterfall), cycles (agile), hierarchies, to dynamic and adaptive topologies that evolve with task complexity (e.g., EvoMAC, FlowReasoner).
*   **Execution Feedback and Shared-Harness Synchronization:** Code's executability provides objective feedback and facilitates consistent state.
    *   **Execution Feedback:** Compiler/syntax errors, test pass/fail, fuzzer crash traces, static analysis warnings, performance profiling, and fine-grained simulation feedback (e.g., AgentCoder, AutoSafeCoder, MAGE).
    *   **Shared-Harness Synchronization:** Mechanisms like sequential handoff, shared blackboards, parallel branches with merge, structured context scheduling, hierarchical memory, and agent pool scaling maintain consistent program state.
*   **Shared Code-Centric Harness Substrate (Position):** Emphasizes the need for formal, persistent representations of shared code state.
    *   **Implicit, Repository-based, Execution-based, Blackboard Representations:** Describes varying degrees of formality in shared state, with the "blackboard" offering the closest approximation to a formal harness substrate.
*   **Harness-State Convergence:** Criteria for stopping iteration.
    *   **Correctness (test-gated), Security, Performance, Score-based, Consensus, Implicit:** Convergence can be objectively grounded in test results, security checks, performance metrics, or through multi-agent consensus, moving beyond implicit termination.

**5.4. Application Domains:** The paper illustrates these concepts across coding assistants, GUI/OS agents, embodied agents, scientific discovery, and personalization, demonstrating how code serves as an operational substrate for real-world agentic systems.

### 6. Significance and Potential Impact

The paper's significance lies in its conceptual framing of "code as agent harness," which provides a unified and systematic understanding of the evolving role of code in AI agent systems. This perspective shifts the focus from code generation as an end product to code as an **executable, inspectable, and stateful operational substrate** that enables and governs agent intelligence.

The potential impact is multi-faceted:

*   **Foundation for Reliable AI Agents:** By emphasizing the harness—the software layer surrounding the LLM—the paper highlights the critical engineering challenges necessary for building reliable, long-horizon, and adaptable AI agents. This moves beyond focusing solely on base model capabilities to addressing system-level robustness.
*   **Structured Research Roadmap:** The proposed three-layered taxonomy (Harness Interface, Mechanisms, Scaling) provides a structured framework for researchers to categorize existing work, identify gaps, and guide future development in agentic AI. It promotes a more holistic understanding of agent architectures.
*   **Bridging AI and Software Engineering:** The framework deeply integrates concepts from software engineering (e.g., version control, testing, debugging, CI/CD, formal methods) into the design and evaluation of AI agents. This fosters interdisciplinary collaboration and the adoption of robust software development practices for AI systems.
*   **Impact on Specific Application Domains:** The detailed analysis of applications (coding assistants, GUI/OS agents, embodied agents, scientific discovery, personalization) demonstrates the broad applicability and tangible benefits of the "code as agent harness" paradigm. This includes developing more autonomous coding tools, generalist computer-using agents, verifiable robotic policies, self-driving laboratories, and adaptive recommendation systems.
*   **Highlighting Critical Open Problems:** The identification of key open challenges—such as harness-level evaluation, semantic verification beyond executable feedback, regression-free self-evolving harnesses, transactional shared state, and human-in-the-loop safety—serves as a crucial agenda for future research and development. Addressing these problems is essential for the safe and effective deployment of AI agents in complex, real-world environments.
*   **Emergence of "Harness Engineering":** The paper implicitly advocates for the recognition of "harness engineering" as a distinct scientific discipline. This new field would focus on designing, measuring, and optimizing the operational substrates that turn stateless models into functional, governed, and verifiable agents. This could lead to new tools, methodologies, and benchmarks specifically tailored for agent system development.

In summary, this work provides a foundational shift in how AI agent systems are conceptualized, moving towards a vision where code is central to not just what agents produce, but how they function, interact, and evolve reliably in complex environments. This framework is poised to influence the next generation of AI agent design and engineering practices.
