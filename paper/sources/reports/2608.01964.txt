### Research Report: LongHorizon-Harness

#### 1. Authors and Institution(s)

The authors of this research are Ziyu Ma, Hailang Huang, Shun Zou, Yong Wang, Shidong Yang, Yiming Hu, Fei Wei, and Xiangxiang Chu. All authors are affiliated with the DreamX Team, Alibaba Group. Ziyu Ma, Hailang Huang, Shun Zou, and Yong Wang contributed equally to this work, with Yong Wang serving as the project lead.

#### 2. How This Work Fits into the Broader Research Landscape

The development of large language models (LLMs) has led to their increasing application as the decision-making core for autonomous agents across various domains, including software engineering, general-purpose assistance, scientific discovery, and human-computer interaction. These agents are increasingly tasked with "long-horizon execution," which demands sustained reasoning, sequential tool use, observation, and iterative revision over numerous interdependent steps, often spanning multiple context windows or sessions. The ability of agents to successfully complete long-horizon tasks is becoming a critical determinant of their utility and the scope of work that can be delegated to them.

However, current LLM agent systems face significant challenges in long-horizon execution. These challenges include:
*   **Compounding errors and goal drift**: Errors in early actions or decisions can accumulate, leading to deviations from the original task objective.
*   **Context rot**: As interaction history grows, the increasing size of the context window makes it difficult for agents to retrieve and utilize relevant information, potentially degrading performance.
*   **Task-state loss**: Agents often struggle to accurately capture, retain, and update the comprehensive task state (i.e., requirements, completed actions, produced artifacts, and discovered facts) throughout the execution of complex, multi-step tasks.

Existing efforts to enhance agent capabilities have focused on both scaling LLM backbones (e.g., increasing model size, context windows, and training on high-quality data) and improving agent harnesses. These harnesses provide a systemic layer for organizing prompting, tool use, context management, and multi-step execution, often incorporating features like planning, task decomposition, and subagents. Nevertheless, the paper identifies two structural limitations in existing harnesses:
*   **Coupled task execution and task-state management**: The same growing context is used for both executing tasks and maintaining the task state, making effective state tracking increasingly difficult as the execution history expands.
*   **Coupled task execution and completion assessment**: Agents perform subtasks and also judge their own completion. An inaccurate self-assessment can be erroneously integrated into the task state, propagating incorrect premises to subsequent decisions.

LongHorizon-Harness directly addresses these structural limitations by proposing a novel framework for managing task state and verifying progress, thus aiming to enhance the reliability and robustness of LLM agents in long-horizon scenarios.

#### 3. Key Objectives and Motivation

The primary motivation behind this research is to overcome the inherent difficulties faced by LLM agents in reliably executing long-horizon tasks in real-world environments. Existing approaches, while advancing individual agent capabilities, are hampered by systemic issues related to context management, error propagation, and inconsistent task state maintenance. The paper argues that the coupling of execution, state management, and self-assessment within a single, growing context window leads to compounding errors, context rot, and task-state loss, ultimately limiting the practical applicability of LLM agents for complex, multi-step tasks.

To address these limitations, the key objectives of the LongHorizon-Harness framework are:

1.  **Reformulate long-horizon execution as a task-state management problem**: Instead of viewing long-horizon tasks as a continuous, ever-growing single trajectory, the framework re-conceptualizes them as a sequence of discrete, independently auditable task-state transitions. This aims to impose structure and clarity on complex execution workflows.
2.  **Explicitly maintain task state outside execution**: A core objective is to separate the dynamic, potentially noisy process of task execution from the stable, persistent record of task state. By keeping the task state (comprising requirements, artifacts, and discovered facts) external to the executor's ephemeral context, the framework intends to prevent context rot and make the state easier to track and manage.
3.  **Ensure task state updates are based only on independently verified facts**: To mitigate the propagation of incorrect self-assessments, a critical objective is to mandate that the task state is updated exclusively with information independently validated from the environment. This introduces an external, objective verification mechanism to confirm progress and detect errors.
4.  **Derive each subsequent subtask from the current, verified task state and the original goal**: By relying on a consistently updated and independently audited task state, the framework aims to enable a manager component to intelligently plan the next subtask, ensuring coherent progress towards the overall goal and facilitating recovery from failures.
5.  **Support interchangeable model and harness backends**: To ensure broad applicability and flexibility, the framework aims to integrate with existing LLM backbones and agent harnesses through a lightweight adapter. This allows researchers and developers to leverage the framework's benefits without requiring fundamental changes to their preferred underlying models or execution environments.

By achieving these objectives, LongHorizon-Harness seeks to provide a more robust and reliable approach to long-horizon agent execution, enabling LLMs to handle more complex and sustained real-world tasks effectively.

#### 4. Methodology and Approach

LongHorizon-Harness is designed to manage long-horizon agent execution by reframing it as a series of independently audited task-state transitions, rather than a single, continuously expanding session. The core principle involves maintaining an explicit task state external to the execution process, updating this state solely with independently verified facts from the environment, and deriving subsequent subtasks based on this verified record and the original goal. The executor's raw interaction trajectory is discarded after each round, ensuring that only compact, verified task state persists.

The framework operates through a **Manage-Execute-Audit (MEA) loop**:

1.  **Manager**:
    *   **Role**: The manager is responsible for owning and maintaining the persistent task state and determining the overall task progression. It acts as the central orchestrator of the MEA loop.
    *   **Information Access**: It has access to the original task definition (T), the current explicit task state (S_i), and all accumulated audit reports (V_i). Crucially, the manager has no direct interface to the computer environment; its decisions are based entirely on internal state and verified environment evidence.
    *   **Task-State Update**: After each round, the manager updates the task state (S_i+1) by applying the verified findings from the latest audit report (v_i) to S_i. The task state is a structured collection of records (requirements, artifacts, facts), each marked with a status (completed, pending, blocked, untrusted). Executor claims alone do not alter the persistent state; completion status requires clean audit evidence.
    *   **Next-Subtask Construction**: By comparing the updated task state (S_i+1) against the original task (T), the manager identifies an unresolved objective that can be advanced. It then constructs a *bounded subtask contract (c_i+1)*. This contract specifies the immediate goal, acceptance criteria, boundary constraints, and any relevant prior task-state records or audit reports needed for execution and verification. The contract is routed to either a GUI or CLI executor based on the primary environment transition required.
    *   **Control Decisions**: The manager determines whether to `execute` another round (with c_i+1), declare the task `done` (if audited state satisfies T), mark it `blocked` (if no permitted action can advance requirements), or request `ask` (if user input/authorization is needed).

2.  **Executor**:
    *   **Role**: The executor performs the specific subtask contract defined by the manager. It is the only component permitted to intentionally modify the environment.
    *   **Input**: In round i, it receives the original task (T), current task state (S_i), the subtask contract (c_i), and only the *prior audit reports specifically referenced by the contract*.
    *   **Fresh-Context Execution**: Each executor invocation runs as a new, budget-bounded episode. It does not receive the raw interaction trajectories or internal reasoning from previous rounds. Within this isolated episode, the executor can perform multiple cycles of planning, environment interaction, observation, and revision.
    *   **Output**: Upon completion, its raw trajectory and internal reasoning are discarded; only an *execution report (o_i)*, summarizing actions and resulting state, is forwarded for auditing. This report describes the executor's outcome but does not establish completion.
    *   **Capability Boundaries**: The framework segregates GUI and CLI capabilities. A GUI executor uses screen-oriented tools (screenshots, clicks, text input) for application/interface state. A CLI executor uses shell execution, file editing, coding, and testing for workspace/process/program state. The harness exposes only the toolset assigned to the selected executor role.
    *   **Backend Execution**: Executors are instantiated via a lightweight **AgentAdapter** interface. This adapter allows existing agent backends (e.g., Claude Code, Codex CLI, OpenClaw) to be launched within the bounded episode, retaining their native planning and tool-use loops. The harness controls the supplied context, available tools, environment permissions, execution budget, and report generation.

3.  **Auditor**:
    *   **Role**: The auditor independently verifies the state of the environment (e_i) after the executor's actions, ensuring that changes align with the subtask contract.
    *   **Input**: It receives the original task (T), task state (S_i), contract (c_i), referenced prior audit reports, and the executor's report (o_i). It does *not* receive the executor's raw interaction trajectory or internal reasoning, ensuring independent assessment.
    *   **Independent Environment Inspection**: Starting from a fresh context, the auditor inspects e_i using *read-only tools*. It compares the resulting environment against the goal, acceptance criteria, and boundary constraints specified in c_i. A GUI auditor examines application/screen state; a CLI auditor uses non-mutating commands for files, logs, and processes.
    *   **Read-Only Authority**: The auditor cannot modify task-relevant environment state. Any detected mutation during auditing is recorded as an integrity violation, preventing its report from validating a completed task-state record.
    *   **Audit-Result Construction**: The auditor produces an *audit report (v_i)*. This report includes a completion status (complete, incomplete, blocked), an integrity status (clean, suspect, violation), and details on task-state updates supported by its inspection (verified facts, supporting evidence, remaining gaps). This v_i is then appended to the persistent audit history and returned to the manager.

This MEA loop, facilitated by the AgentAdapter, ensures that task progress is based on external, verifiable evidence, enabling more robust recovery from errors and consistent advancement towards complex long-horizon goals.

#### 5. Main Findings and Results

The evaluation of LongHorizon-Harness demonstrates consistent performance improvements across various long-horizon benchmarks and model backbones.

**Quantitative Performance Improvements:**

*   **WeaveBench (114 tasks: hybrid GUI–CLI coordination)**:
    *   Using Qwen 3.7-Plus with Claude Code, the baseline achieved a PassRate of 51.8% and an average task score (Overall) of 0.702.
    *   LongHorizon-Harness, utilizing the same Qwen 3.7-Plus model and Claude Code as its executor backend, significantly improved these metrics to an 80.7% PassRate and an 0.835 Overall score. This represents a substantial gain, nearly doubling the strongest officially reported result of 41.2% by Claude Opus 4.7 with Claude Code.
    *   Performance gains were observed across all eight task domains, with notable PassRate improvements such as Design (+60.0 percentage points) and Spatial/3D Applications (+50.0 percentage points).

*   **OSWorld 2.0 (108 tasks: professional desktop workflows)**:
    *   With Qwen 3.7-Plus as the backbone, the baseline achieved 2.8% Binary completion (tasks with a final score of 1) and a 21.5% Partial score (average score over all tasks).
    *   LongHorizon-Harness increased Binary completion to 8.3% (a threefold improvement) and Partial score to 35.2%.
    *   On a 34-task subset of OSWorld 2.0, LongHorizon-Harness with Claude Opus 4.7 improved Binary completion from 20.6% to 35.3% and Partial score from 55.8% to 66.9%.

*   **Terminal-Bench 2.1 (command-line tasks)**:
    *   For Qwen 3.7-Plus with Claude Code, the baseline achieved a success rate of 69.7%.
    *   LongHorizon-Harness improved this to 77.2% with the same model and executor.
    *   When using Codex as the executor backend with GPT-5.6 Luna, LongHorizon-Harness further achieved an 83.1% success rate.

**Analysis of Results:**

*   **Complementarity with Backbone Capability**: The consistent improvements observed with both Qwen 3.7-Plus (a less powerful model compared to frontier models) and Claude Opus 4.7 (a more advanced model) indicate that LongHorizon-Harness offers complementary gains. The LLM backbone determines the quality of actions and decisions within a single round, while the harness determines how reliably verified outcomes are maintained and utilized across multiple rounds.
*   **Cost–Performance Trade-off**: On OSWorld 2.0, achieving the performance gains with Qwen 3.7-Plus led to an increase in average output token consumption from 28.9K to 104K per task. This suggests that the harness can significantly boost task-level performance for a given model, often with increased computational cost associated with the additional verification and potential recovery rounds. However, the token cost is not fixed and varies by task and model, sometimes even reducing cost (e.g., 24% fewer tokens on Terminal-Bench 2.1 with higher success rate).
*   **Computation Across Roles**: The manager component accounts for a low proportion of total tokens (2.0–8.1%), indicating that explicit task-state maintenance introduces minimal computational overhead. The auditor, responsible for independent verification, constitutes the main additional investment in tokens (19.4–38.1%).
*   **Task-Dependent Effectiveness**: LongHorizon-Harness showed larger improvements in tasks requiring agents to preserve, inspect, and revise multiple dependent environment states over an extended trajectory. These included tasks in WeaveBench's Design, Spatial/3D, and Games domains; OSWorld 2.0's streaming interaction, human-in-the-loop, and tutorial-following tasks; and Terminal-Bench 2.1's system administration and software engineering categories. Less benefit was observed in analytical categories where performance is dominated by a single model capability (e.g., visual perception, mathematical reasoning), as the harness cannot compensate for a lack of fundamental model capability.
*   **Agent Capability as a System Property**: The research highlights that agent capability is a property of the complete model–harness system. For instance, Qwen 3.7-Plus with LongHorizon-Harness achieved a mean score of 0.733 on WeaveBench Games, surpassing Claude Opus 4.7 with the baseline Claude Code harness (0.680). This demonstrates that a stronger harness can elevate the task-level performance of a less powerful model by improving how local capabilities are decomposed, verified, and accumulated.

**Case Studies (Qualitative Analysis):**
Qualitative analysis through case studies illustrated how LongHorizon-Harness addressed common failure modes:
*   It externalized stalled GUI interactions as unresolved state, allowing subsequent executors to resume from audited progress rather than a failed trajectory.
*   It prevented misinterpretations of completion by having an independent auditor verify semantic environment state (e.g., document XML) instead of relying on visually plausible but non-compliant executor claims.
*   It ensured consistent evidence chains by explicitly tracking and recording pre-repair evidence as pending requirements before allowing environment modifications.
*   It maintained continuity for long workflows by preserving verified progress in the task state, enabling fresh-context executors to focus on remaining deliverables without regenerating or carrying preceding processes.

#### 6. Significance and Potential Impact

The introduction of LongHorizon-Harness represents a structural advancement in the field of autonomous LLM agents, offering a novel paradigm for reliable long-horizon execution. Its significance and potential impact are multifaceted:

1.  **Fundamental Reformulation of Long-Horizon Execution**: By reformulating long-horizon execution from a single, growing trajectory into a sequence of independently audited task-state transitions, the framework provides a more structured and robust approach to managing complexity. This shift addresses core challenges like context rot and compounding errors by preventing the accumulation of irrelevant history and unverified claims within a single interaction context.
2.  **Enhanced Reliability and Robustness**: The consistent and substantial performance improvements across diverse benchmarks (WeaveBench, OSWorld 2.0, Terminal-Bench 2.1) and varied interaction domains (hybrid GUI–CLI, desktop, pure command-line) demonstrate a significant increase in agent reliability. This implies that agents powered by LongHorizon-Harness are less prone to getting stuck, propagating errors, or failing to converge on complex tasks, making them more dependable for real-world applications.
3.  **Clarifying Agent Capability as a System Property**: The research emphasizes that the overall capability of an LLM agent is a function of the entire model–harness system, not solely the underlying language model's intrinsic abilities. By demonstrating that a sophisticated harness can enable a less powerful model to outperform a stronger model with a basic harness, the work encourages a holistic view of agent design. This could lead to more efficient resource allocation in agent development, focusing on optimizing the system rather than just scaling models.
4.  **Promoting Independent Verification and Accountability**: The explicit Audit role, with its read-only authority and independent verification of environment state, introduces a critical layer of accountability. This mechanism ensures that task state progresses only based on objectively confirmed facts, fostering greater trust in agent performance and providing clear debugging points when issues arise. This concept has implications for safety and trustworthiness in autonomous systems.
5.  **Generalizability Across Models and Tasks**: The lightweight AgentAdapter ensures compatibility with various LLM backbones and existing agent harnesses. This broad compatibility means that the benefits of LongHorizon-Harness are not confined to a specific model or environment, enhancing its potential for widespread adoption and further research. The effectiveness observed across different task types, particularly those requiring sustained state management, underscores its broad applicability.

The potential impact of LongHorizon-Harness lies in enabling LLM agents to tackle more ambitious and real-world tasks that demand sustained, coherent progress and reliable execution over many steps. This could accelerate automation in areas such as complex software engineering, advanced scientific discovery, intricate data analysis, and sophisticated general-purpose assistance, ultimately expanding the practical frontier of what autonomous AI agents can achieve.
