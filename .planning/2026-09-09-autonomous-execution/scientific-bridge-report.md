# Scientific bridge lane

Status: complete for this bounded lane. 22/22 focused synthetic tests pass, including real Docker fit/predict. Actual dataset access and live ORX scientific launches: zero.

Plan completed: shared resource API and ORX CLI contract; sandbox candidate entry and committed-spec runner; admission, immutable snapshots, ORX lifecycle and final lock; synthetic verification and handoff report.

Ownership: scientific_bridge.py, candidate_entry.py, runner.py, test_scientific_bridge.py and this report pair. Root owns the native episode controller, project registration and main planning files. The kernel lane owns resource admission and the shared native REPL boundary.

Verified ORX 0.1.120 CLI surfaces: create-experiment; exp run --backend local; exp status; runs; logs; exp wait. Commands and environment stay fixed across nodes. Generated code may only consume train data during fit and feature data during prediction; it never runs in the trusted scorer process. Previously validated ORX text parsers were read in full for bounded reuse. No dataset or actual scientific run will be used by this lane.

CLI: `/opt/homebrew/bin/python3 scientific_bridge.py --episode-config <host-control-config> <action>` with one JSON object on stdin. Public actions: `run_candidate(relative_source="solution.py", config={}, hypothesis, parent_experiment_id=None)`, `list_results()`, `lock_candidate(candidate_id)`. Host-only actions: `initialize()` and `finalize()`. Root initializes the charged RF100 baseline before model research. Finalize falls back to the registered default and returns only `FINAL_WITHHELD`; actual final metric is stored in the private receipt and ORX log.

Episode config consumes `workspace`, `custody_task_root`, `metadata` (public object or host path), `private_artifact_dir`, `kernel_config`, `projectId`, `projectPath`, immutable `image`, `deadline_epoch`, optional `orx_executable` and `parent_experiment_id`. The private artifact directory and config must be inside the episode's unmounted `control/`; all research paths remain under the dedicated study root. Metadata uses `row_counts.dev`, `row_counts.test`, and `files_sha256` from the data-custody implementation. Source reads use descriptor-relative traversal with no-follow checks, including every parent directory, and reject hard links.

ORX fixed command is `/opt/homebrew/bin/python3 runner.py`, revised prospectively by root to use the verified host interpreter. Root registers the private project and initial episode node. `kind="episode"` dispatches the committed `controller.ts` with the host config path and accepts exactly a `study-episode-summary/v1` JSON result. `candidate` and `final` nodes commit their source, frozen config, public schema, runtime hashes and node spec into dedicated private worktrees. Observed candidate parents bind the recorded parent commit; baseline may descend from the host-authorized running episode node. Existing nodes are never edited, merged, rebased or pushed. The bridge records launch intent before invoking ORX, checks status/runs/commit correspondence and consumes only a complete safe JSON log receipt.

Candidate code implements `fit(train_X, train_y, frozen_config)` and returns an object with `predict(X)`. Only `candidate_entry.py`, `solution.py`, frozen config and public schema are mounted in the sandbox app directory. The host-only scoring module is never mounted. Fit receives the chosen training CSV only; prediction receives the fitted model and feature CSV only. Generated stdout/stderr are discarded; deserialization occurs only in the prediction sandbox. Host scoring validates integer class IDs and prediction length before reading the private label file. Custody input hashes are checked against the frozen metadata.

Feedback slots are consumed before the ORX operation, including known candidate failures. The baseline consumes slot 1, slot 13 is refused, exact recipe requests reuse the same receipt, and pending/unknown intents do not relaunch. One verified explicit final lock is idempotent; changing it is refused. The final refit counter is persisted before launch and recipe/source identity is rechecked. Final score never appears in list_results or finalize responses.

Shared resources use `load_config`, `reserve_resources`, `remaining_cpu_seconds`, `remaining_seconds` and `release_resources` from the kernel wrapper. Fit/predict allocate 1.5 CPU and 4 GiB, sharing the 2 CPU/8 GiB episode pool with native kernels. Development stops before spending the reserved 900 CPU seconds or final 600 wall seconds. Container watchdogs survive owner process death; release occurs only after an empty Docker container listing confirms cleanup. Containers have no network, a read-only root/app/input, nonroot UID, dropped capabilities, no-new-privileges, equal memory/swap caps, 128 PIDs, bounded temporary storage, per-file output limits and aggregate output monitoring.
