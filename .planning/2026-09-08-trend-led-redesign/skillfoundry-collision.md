# SKILLFOUNDRY: 경험 전이 후보와의 직접 충돌 확인

판정: **과학적 실행 기술의 자동 생성·검증·개선과 그 하위 과제 효용은 이미 연구되었다. 그러나 이 v1은 자기 선행 연구 경험이 미관측 새 데이터셋의 연구를 개선하는지, 경험 생성비까지 포함하면 언제 이익이 되는지를 직접 평가하지 않는다.** 따라서 좁은 실험 질문은 남지만, 이것만으로 전체 선행연구에 대한 독창성이 확립되지는 않는다.

최신 사용자 지시에 따라 비교 대상은 기존 frontier LLM을 사용하는 **하네스·연구 방법론**이다. 경험 학습은 외부 절차·도구·작업 방식의 갱신이며 LLM 가중치는 고정한다. 새 LLM 개발이나 가중치 학습을 제안하지 않는다.

특히 Appendix A.1.3은 기술이 단순히 실행되는지를 넘어서, `skill versus no skill` 비교가 약하면 최적화하고 다시 벤치마킹한다고 설명한다(LF 819–825). 따라서 “성공 사례를 기술로 만들고 검증하는 반복 루프” 정도로만 설명하면 이 후보의 구분이 사라진다.

71.1%의 “novel skills”는 SkillHub/SkillSMP에서 같은 작업의 기술이 검색되지 않는다는 논문의 라이브러리 중복 판정이다(LF 437–445). 71.1%의 새 과학 발견, 미관측 과제 전이 성공률 또는 방법론의 독창성 수치가 아니다.

## 3. 남는 질문이 이 논문에서 이미 평가되었는가

| 확인 항목 | 보존 v1에서 확인한 평가 | 좁은 경험 전이 질문과의 차이 |
|---|---|---|
| 경험의 원천 | heterogeneous scientific resources에서 추출. §2가 trajectories·failures·RL·manual engineering을 주원천으로 하는 기존 연구와 구별한다고 명시한다(LF 140–150). | 같은 연구자가 과제 A를 직접 수행하면서 얻은 실험·실패·선택의 기록으로부터 배우는 비교가 아니다. |
| 순차적 연구 경험 | 자원 채굴→실행 기술 생성→검증·최적화→라이브러리 갱신의 순환이다. | 독립된 source 연구 과제군을 수행한 뒤 target 과제군을 처음 푸는 명시적인 경험 수집/전이 평가 분할은 보고하지 않는다. |
| MoSciBench 여섯 데이터 | 보유 기술 라이브러리 유무 비교이며 모든 여섯 데이터에 실행 성공률 100%를 보고한다(LF 468–495). | 라이브러리 획득 자료에서 평가 데이터/과제군을 배제하는 명시적인 프로토콜이나, source own-research와 target의 구분은 보존 전문에 없다. 이것은 누출이 있었다는 판정이 아니라, 이 자료만으로 미관측 자기경험 전이를 확인할 수 없다는 뜻이다. |
| Cell type annotation | 개발 중 인간 심장 MERFISH 하나의 데이터와 목표 prompt를 받은 후 관련 자원을 찾고 기술을 만든다(LF 509–517). | 평가 target을 보기 전에 과거 다른 데이터셋 연구에서 학습한 기술의 전이가 아니다. |
| scDRS “transfer” | 요청한 scDRS 기술을 외부 과학 에이전트 Biomni에 제공한다. TMS FACS + height GWAS 한 워크플로, 군별 3회 실행(LF 550–569). | **에이전트 사이 이식**이다. 과거 과제에서 새로운 데이터셋/과제로의 전이와 구분해야 한다. |
| 강한 고정 실행 절차 | annotation에서는 SpatialAgent도 비교하되 도구·외부 참조 데이터 사용이 다르다. scDRS는 Biomni 기본 지식/워크플로에 없다고 설명한다(LF 533–556). | 동일 연구자에게 동일한 강한 고정 기본 절차를 준 상태에서 원시 노트와 자기 학습 절차를 비교하지 않는다. |
| 원문 연구 노트 대조군 | 보고된 주요 비교는 skill/no-skill이다. | 같은 자신의 경험을 원문 노트로 검색하는 것보다 절차화가 나은지 분리하지 않는다. |
| 전체비용과 회수점 | 단계별 평균 실행 시간을 보고하며, 고정 자원 탐색 예산의 runtime이고 API token usage가 아니라고 명시한다(LF 446–452). | 경험 수행·추출·검증·유지와 새 과제 실행까지 합친 matched-budget 비교나 비용 회수점 K*를 보고하지 않는다. |

**직접 답:** 이 보존 v1만 기준으로 하면 “자기 선행 연구 경험 → 미관측 새 데이터셋의 연구 효용 → 전체비용 회수점”의 결합은 이미 평가된 실험이 아니다. 다만 논문은 경험·trajectory 계열 연구를 관련연구로 구분하므로, “자기 경험에서 배우는 발상”의 최초성도 이 차이에서 따라오지 않는다. Skill-Pro, Agent Workflow Memory, ReasoningBank 및 이후 버전을 별도로 확인하지 않은 상태에서는 전체 문헌의 공백을 확정하면 안 된다.

## 4. 실제 결과가 주는 설계 교훈

Cell type annotation에서 생성 기술을 받은 Codex의 정확도는 68.5 → 82.9%로 좋아지지만 SpatialAgent는 87.1%이다(§4.3, LF 534–544). 서로 다른 참조 데이터 사용 때문에 순수한 기술 학습 효과 비교는 아니지만, **좋은 고정 전문 연구자가 더 강할 수 있다**는 대조군 선택 이유가 된다. 약한 no-skill 에이전트만 이겨서는 충분하지 않다.

scDRS에서는 평균 RMSE가 0.11 → 0.02로 감소하지만, 생성 기술을 받은 세 실행 중 한 실행만 모든 7개 정성 기준을 만족한다. 다른 한 실행은 RMSE 0이면서 정성 점수 3이다(Appendix Table 2, LF 952–973). 수치 재현과 완전한 연구 산출물은 다르므로, 제안 실험도 최종 예측 점수와 실행·보고 유효성을 함께 확인해야 한다. 이는 본 lane의 해석이며 새 측정 결과가 아니다.

실행 시간 그래프는 자원 채굴 320.0초, 기술 추출 622.1초, 실행 시험 201.2초, 합성 데이터 시험 207.1초, 트리 갱신 60.5초를 제시한다(Figure 2, LF 264–296; 설명 LF 446–452). 이것을 달러 비용이나 새 연구 한 건당 전체비용으로 바꿔 인용하면 안 된다. 추출과 검증이 공짜가 아니라는 동기는 되지만, 제안 방법의 손익분기점은 직접 측정해야 한다.

## 5. 설계에 반영할 경계

핵심 질문은 “과학용 기술 라이브러리를 만들 수 있는가”에서 끝나면 안 된다. **동일한 강한 연구자**에게 ① 고정 실행 가능한 기본 절차, ② 같은 기본 절차 + 자신의 원시 연구 기록 검색, ③ 같은 기본 절차 + 자기 경험에서 학습한 재사용 절차를 제공하여 새 데이터에서 비교한다. 평가를 보기 전에 경험 저장소를 고정하고 source/target을 원본 데이터셋 단위로 분리한다.

③이 ①·②를 이기는지 먼저 확인한다. 기술 통합, 압축, 그래프, 트리는 그 결과가 있을 때 조사하는 선택적 구현 문제이다. ③의 이득이 이미 받은 정답·잘된 설정·해당 과제 전용 템플릿을 옮겨 온 효과라면 과제 전이 주장은 기각한다. 실제로 수행하지 않은 과거 연구를 문헌에서 가져왔다면 이 논문의 자원 채굴과의 경계가 약해진다.

주어진 작은 공개 ML 계획은 이 차이를 측정할 수 있으나, 결과가 성공해도 처음의 “범용 과학 연구 능력 학습”을 입증하지 않는다. 정확한 결과 문구는 “고정한 공개 ML 과제 분포에서 자기 선행 실험 기록을 실행 절차로 바꾸었을 때의 새 데이터 전이와 비용”이다.

작업 상태: 전문 읽기 및 충돌 평가 문서만 완료. 효용, 구현, 비용 회수점, 독창성의 최종 확정 또는 실험 실행은 완료하지 않았다.
