# 후보: 실제 실험 전에 AI 연구자가 싸게 연습할 수 있을까?

판정: **이번 연구의 주제로는 기각. 실행 가능한 연습 환경은 보조 실험 도구로만 보류한다.** Terminal-Universe는 미래 ML 성능의 시뮬레이터도, 고정 LLM의 사전 연습 효과를 검증한 연구도 아니다. 공개 ML 과제에서 원본 환경을 확보할 수 있다면 손실 있는 복원보다 정확한 복제와 소규모 실험이 먼저 비교 대상이 된다. 아래 내용은 가능성을 판별하는 설계이며 실행·효능·독창성 결과가 아니다.

## 한 문장 질문과 메커니즘

**“같은 모델과 총 예산을 쓸 때, AI 연구자가 작은 실행 환경에서 먼저 실험을 끝까지 연습하면 바로 시작하는 것보다 실제 과제의 최종 점수가 좋아지는가?”**

AI가 작은 데이터로 로딩→전처리→학습→검증→결과 저장을 실제 실행하고, 관찰한 문제에 따라 구현이나 실험 선택을 수정한 뒤 본 실험으로 넘어간다. 연구 대상은 추가된 실행 경험의 전이 효과다. 환경 복원 기술 자체, 그래프·기록·승인 절차 수, 거대한 모델 재학습은 기여로 내세우지 않는다.

## 실행 재생과 성능 시뮬레이션

실행 재생은 구체적 파일·프로그램·의존성을 실제로 돌려 그 환경의 동작을 관찰한다. 작은 데이터 시험도 실제 계산이지만 전체 데이터에서의 수렴·메모리 사용·알고리즘 순위를 보존하지 않는다. 미래 ML 성능 시뮬레이터는 실행하지 않은 본 실험의 결과를 예측해야 하므로 별도의 예측 오차와 선택 후회 검증이 필요하다. Terminal-Universe는 이 마지막 주장을 평가하지 않았다.

따라서 “리허설 통과가 본 실험 성공을 보장한다” 혹은 “가짜 환경이 GPU 실험을 대신한다”는 문구는 기각한다. 남길 수 있는 가설은 “작은 실제 실행에서 얻은 수정이 본 실험의 비용 대비 성과를 개선하는가”다.

## 가장 작은 정당한 비교

단일 최종 지표: **동일한 총 자원 예산에서 얻은 비공개 평가 점수**. task별로 metric 방향을 맞춘 paired 차이를 보고, 다른 metric을 합치려면 사전 고정 기준점을 사용한다. 비공개 평가 점수는 마지막에 한 번만 사용하고 모든 실험 선택은 개발 split 안에서 한다. 리허설 횟수·계획의 설득력·잡은 오류의 자기보고는 성과가 아니다.

| 조건 | 사전 행동 | 예산 처리 |
|---|---|---|
| 직접 실행 | 같은 초기 자료로 계획 후 바로 ML 실험 | 모든 실행·수정·재시도를 차감 |
| 강한 통상 비교 | 표준 end-to-end smoke run과 작은 데이터 학습 후 수정 | 사전 시험도 차감 |
| 후보 리허설 | 에이전트가 실험의 불확실성에 맞춘 축소 실행을 구성·수행 후 수정 | 환경 준비·보완·리허설도 전부 차감 |

모델 버전, 기본 프롬프트, 도구, 초기 파일, 개발 데이터, 최대 토큰, 총 실행 자원을 동일하게 둔다. 핵심 상대는 두 번째 조건이다. 첫 번째만 이기면 “실행해 보면 버그를 잡는다”는 설명이 남는다. 복원 자체를 검증하려면 원본 snapshot을 정답 대조로 둬야 한다. 원본을 가진 공개 과제에서 복원을 강제로 도입하지 않는다.

task/seed 쌍은 같은 split·초기 상태로 시작하며 seed 반복을 별도 과제 수처럼 세지 않는다. LLM 재학습은 없다. 평가자는 고정 비공개 데이터와 metric을 사용한다. 이는 필요한 비교 조건이며 새 승인 체계의 기여가 아니다.

## 시연

공개 ML 과제 하나에서 같은 실험안의 복제 환경 둘을 연다. 왼쪽은 표준 작은 데이터 시험, 오른쪽은 에이전트가 고른 리허설 후 본 실험을 진행한다. 화면에는 초기 예산, 실제 소모량, 리허설에서 관측한 문제, 수정 내용, 마지막 비공개 점수만 표시한다. 오른쪽이 리허설을 통과했어도 전체 데이터에서 순위가 뒤집히는 경우를 결과로 남긴다. 시연은 실제 workflow를 실행하며 가상의 점수를 만들지 않는다.

## 새로움의 빈칸과 값싼 반증

- 직접 확인된 빈칸: 이 논문은 고정 모델의 추론 시점 리허설 전이를 실험하지 않았다. 이는 Terminal-Universe와의 차이이며 분야 전체의 독창성 확인이 아니다.
- 가장 위험한 겹침: 일반 사전 점검, 소규모 학습, 낮은 충실도 실험 선택, 학습곡선 기반 자원 할당만으로 효과가 설명될 수 있다. 관련 연구가 없다고 주장하지 않는다. 루트 담당자의 검색 결과와 합쳐 판단해야 한다.
- 저비용 반증: 서로 다른 공개 ML 과제 3개를 개발 전용으로 선정해 고정 모델/예산에서 통상 작은 시험과 후보 리허설을 비교하도록 설계한다. 본 실험까지 실제 실행하고 사전 비용을 차감한 최종 점수를 본다. 개선 신호가 없거나 이득이 환경/입출력 오류 수정뿐이면 주제 승격을 중단한다. 세 과제의 양성 결과도 확증이 아니다.
- 실행보다 앞선 반증: 두 방식의 호출 계획이 동일한 smoke/mini-fit이면 새 메커니즘이 아니므로 더 큰 실험을 진행할 이유가 없다.
- 독립적인 성능 예측을 주장하려면 작은 실행의 추천 순위와 숨겨둔 본 실행 순위의 선택 후회를 검증해야 한다. 이때 주제는 낮은 충실도 ML 실험 선택으로 바뀌고 Terminal-Universe는 핵심 근거가 되지 않는다.

## 의존성·비용·실현 가능성

작은 공개 ML 과제의 원본 파일·명확한 라이선스·고정 실행 이미지·고정 모델 접근·실제 사용량 기록·독립 평가 split이 필요하다. 기록 복원 변형에는 trace와 원본 snapshot 쌍이 추가로 필요하다. 유실 데이터를 LLM이 채운 뒤 원본과 동등하게 취급하지 않는다. 현재 공개 코드/모델/데이터의 배포·라이선스는 이 lane에서 별도 검증하지 않았다.

연습은 공짜가 아니다. 설계 예시로 과제당 각 조건에 10 CPU-min, 3개 과제, 3개 조건을 한 번씩 주면 실행 상한은 90 CPU-min이고 3 seed면 270 CPU-min이다. 이는 **예산 산술**이며 측정된 런타임이나 가격 견적이 아니다. 실제 fit이 이 한도에 끝나는 과제인지 확인해야 한다. 모델 input/output token 상한은 별도로 동일하게 부여하고 요금은 선택 모델에 따라 확인한다. CPU와 GPU 사용량을 한 단위처럼 합치지 않는다.

소규모 환경의 실행·전이 측정은 기술적으로 가능해 보이지만 실제 런타임과 재현성은 미검증이다. 27B/1.42B-token SFT 재현은 저비용 조건에 맞지 않는다. 공개 원본을 가진 상황에서 복원 파이프라인을 새로 만들면 준비·감사 비용이 과제 이득을 넘어설 수 있다.

## 최종 결정과 작업 기록

**주제 후보 기각, 보조 도구 보류.** 질문은 직관적이지만 근거에서 두 번의 전이(코딩→ML 연구, 사후 학습→추론 시점 연습)가 필요하고, 통상 작은 시험과 구분되는 새 메커니즘이 없다. 다른 연구에서 반복 실행 환경이 필요하면 환경 재사용 참고문헌으로 사용한다. 선택한 연구의 실제 실험으로 효용을 확인한 후에만 ARGO 프로토타입 설계로 연결한다. 네이티브 construction pause는 유지한다.

읽기·후보 평가 완료. 실험·학습·설치·credentials 접근·native code 변경 없음. 소유 파일은 rehearsal-candidate.md와 rehearsal-candidate.json뿐이다. 공용 plan/findings/progress 갱신은 루트 담당자에게 전달한다. planning-with-files를 이 전담 기록과 루트 계획으로 적용했다. 한 번의 apply_patch가 같은 경로에 delete/add를 함께 지정해 거부되어 파일에 변화가 없었고, 전담 파일만 직접 쓰는 방식으로 수정했다.

기억의 thesis→prototype 연결과 native pause는 현재 agent-brief/migration-state로 확인했다. 과거 G/C/F 설계와 효과 주장은 재사용하지 않았다. MEMORY.md 88–99는 범위 탐색에만 사용했다.
