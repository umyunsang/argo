# 후보: 연구 경험은 다음 연구를 실제로 싸고 잘하게 만드는가

상태: `CANDIDATE_DESIGN_ONLY`. 실험·성능·독창성·구현 완료를 주장하지 않는다. 작성일: 2026-09-08.

**한 문장 질문:** 같은 AI가 앞서 수행한 연구에서 재사용 가능한 실험 절차를 배웠을 때, 처음 보는 ML 과제를 잘 푸는 데 필요한 총비용이 줄어드는가?

사용자가 보게 될 차이는 “예전 실험을 기억한다”가 아니라 “새 데이터에서는 어떤 실험부터 해야 할지 빨리 판단하고, 필요 없는 실험을 덜 하며, 처음 보는 조건에서는 과거 요령을 버린다”이다. 그래프는 필요성이 확인되면 선택하는 저장 방식이다. 그래프 유무나 계약 보존 자체를 논문의 주제로 삼지 않는다.

학습의 대상은 **하네스가 보관하고 사용하는 실행 절차와 연구 작업 방식**이다. 기반 LLM의 가중치는 고정하며 새 모델 학습이나 frontier model 개발을 제안하지 않는다. 아래 실행 횟수는 이 lane의 비용 점검용 설계 예시이며 root가 선택할 작은 파일럿의 필수 규모가 아니다. 별도 기존 모델에 같은 하네스를 고정해 적용하는 이식성 검증은 root 종합 설계에서 다룬다.

## 2. 이 후보가 추가로 물어야 할 것

새로운 기여 후보는 **경험을 획득·정리하는 투자까지 치른 후에도, 데이터와 과제 조건이 달라진 다음 연구에서 유효한 이득이 남는 범위**를 측정하는 것이다. 실행 절차는 작동 조건, 실행 코드, 성공·실패 관측, 비용 및 출처를 함께 담는다. 예컨대 “정규화 후 선형 모델”이라는 답을 저장하는 대신, 어떤 데이터 진단과 작은 비교 실험을 근거로 그 선택을 했는지와 언제 그 선택을 적용하면 안 되는지를 보존한다.

초기 방법은 파일과 평면 인덱스만으로 충분하다. 독립 과제 두 곳 이상에서 작동한 부분만 하나의 절차로 묶고, 대상 데이터 이름·행·정답·과제 전용 상수를 가져가지 않는다. 부적합한 조건에서는 원문을 확인하거나 처음부터 판단한다. 실행 결과가 없는 LLM의 자기평가는 기술 승격 근거로 삼지 않는다. 이 설계 자체는 기존 경험·기술 학습 연구와 겹칠 가능성이 높으며 독창성 주장이 아니다.

**가장 강한 기각 이유:** 이것이 결국 “좋은 ML 템플릿을 조금 더 짧게 검색하는 기능”으로 끝날 수 있다. 강한 고정 절차 라이브러리가 같거나 더 잘하면, 자체 경험 학습을 새 연구 능력으로 포장할 이유가 없다. SkillZip 재현이나 그래프 압축 비교만 남는다면 사용자 요구에 맞지 않아 이 후보를 버린다.

SkillZip과 후속 SKILLFOUNDRY 외의 논문 결과, 출판 상태 또는 새로움은 이 lane에서 검증하지 않았다. root가 수행하는 집중 확인과 합쳐야 한다. 신선한 주간 다이제스트에 실렸다는 사실은 독창성의 증거가 아니다.

## 4. 작게 실행할 수 있는 공개 ML 실험

**실험 단위:** 한 공개 데이터셋의 제한된 분류 연구 과제. 에이전트는 데이터 진단 → 비교할 모델/전처리 선택 → 제한된 실험 → 최종 파이프라인 및 결과 설명을 제출한다. 주장 범위는 “새 공개 데이터셋에서의 실험 전략 전이”이다. 새로운 과학 가설 발명이나 모든 분야의 과학 학습까지 확장하지 않는다.

**실험 규모 제안:** 경험 과제 6개, 평가 과제 8개, 실행 반복 2회. 데이터셋이 추론 단위이며 두 seed를 별도 과제로 세지 않는다. 8개 평가 과제는 방향을 고르는 작은 파일럿이지, 작은 효과의 범용성을 확정할 규모가 아니다.

**공개 데이터 후보:** UCI/OpenML에 배포된 작은 분류 데이터에서 경험군과 평가군을 정한다. 예시 경험군은 Wine, Seeds, Banknote Authentication, Glass Identification, Yeast, Breast Tissue; 예시 평가군은 Ionosphere, Sonar, Balance Scale, Car Evaluation, Dermatology, Dry Bean, Optical Digits, Vehicle Silhouettes이다. 이는 데이터 후보 목록이며, 정확한 릴리스 ID·라이선스·원본 중복·수치/범주형 조건·실제 계산량을 이 lane에서 확인하지 않았다. 확인 뒤 한 번 고정한다. 같은 데이터의 다른 OpenML 버전이나 데이터 변형은 독립 새 과제가 아니다.

선택 조건은 최대 20,000행, 100개 특징, 로컬 CPU로 정해진 모델군을 비교할 수 있는 규모이다. Logistic Regression, RBF SVM, Random Forest, HistGradientBoosting 같은 제한된 후보와 전처리 선택을 쓰고, 에이전트가 다음에 어느 비교를 실행할지 정하도록 한다. 라이브러리와 버전은 실행 준비 때 고정한다. 모델군은 선행 결과가 아니라 비용을 제한하기 위한 설계 선택이다.

학습/내부검증/최종평가를 분리하고, 최종평가 정답과 점수는 에이전트·추출기·검색기에서 숨긴다. 학습 코드만 제출받아 독립 프로세스에서 재실행한다. 같은 데이터의 행, 최종예측, 과제 전용 임계치가 경험 저장소로 넘어오지 않게 한다. 공개 데이터이므로 기반 LLM의 사전학습 노출은 제거했다고 주장하지 않는다. “새로움”은 이번 경험 수집과 실험 프롬프트에 대한 미노출을 뜻한다.

**주 비교군 3개:**

| 군 | 제공하는 경험/절차 | 구분하는 원인 |
|---|---|---|
| A. 강한 고정 연구자 | 평가 데이터를 보지 않고 작성·검토한 실행 가능한 전처리·모델선택·실험설계 절차. 실행 중 진화 없음 | 일반적인 좋은 ML 지침을 넘는 경험의 가치 |
| B. A + 연구 노트 검색 | 동일 경험 과제의 원문 코드·실험 기록·실패·결과를 강한 검색으로 제공 | 원시 기록만으로 이미 충분한가 |
| C. A + 학습한 실행 절차 | B와 동일 기록에서 추출·검증한 재사용 절차를 제공 | 자기 연구 경험을 절차로 바꾸는 추가 가치 |

검색기, 모델, 도구, 에이전트 기본 프롬프트, 최대 문맥과 검색 횟수 정책은 맞춘다. 각 군의 기록 형식과 실제 주입량은 처치이므로 관측값을 기록한다. B를 일부러 약한 top-k 또는 짧은 문맥에 가두지 않는다. A는 읽기 쉬운 고정 레시피뿐 아니라 실행 가능한 기본 코드를 가져야 한다. 고정 절차 작성 비용은 별도 공개하며, 보수적 분석에서는 이미 존재하는 공용 라이브러리처럼 초기 비용 0으로도 계산한다.

경험 생성 기록은 반복별로 한 벌 만든 뒤 B/C가 같은 기록을 사용한다. 평가 8개는 **각 과제 시작 시 같은 경험 스냅샷으로 복원**하여 뒤 평가 과제의 결과가 앞선 학습으로 새지 않게 한다. 따라서 주 실험은 source→unseen target 전이다. 장기간 온라인 적응은 후속 실험이며 이 파일럿에서 같이 증명하지 않는다.

6×2=12개 경험 실행과 8×3×2=48개 평가 실행, 합계 **60개 에이전트 실행**이다. 추출·검증 호출 및 별도 개발용 난이도 점검은 추가 비용이며 이 수에 숨기지 않는다. 숫자는 실행 예산 제안이며 실행 결과나 승인된 비용 한도가 아니다. 통합하지 않은 절차와 통합한 절차의 비교는 C가 먼저 유효할 때만 수행하는 선택적 후속 진단이다. 그래프 압축·매크로 통합을 주 실험의 필수 기능으로 넣지 않는다.

## 5. 주 지표, 비용과 반증

**주 지표:** 경험 획득과 정리에 든 비용까지 차감한 동일 총예산에서, 처음 보는 8개 과제의 최종 재현 가능한 파이프라인이 얻는 평균 최종평가 balanced accuracy. 유효한 제출이 없거나 시간초과·예산초과이면 해당 시점 점수는 0이다. 최초의 기본 파이프라인과 이후 각 개선 제출의 점수·누적비용을 저장하여 품질–비용 곡선을 만든다. 실패 후 몰래 재실행하여 최고 결과만 고르지 않는다.

총예산은 개발 과제의 실측으로 고정한다. 주 실험의 평가 결과를 보고 예산이나 합격선을 고르지 않는다. A에는 경험을 만들지 않아 절약한 비용을 평가 과제의 추가 추론·실험에 사용할 수 있게 한다. 별도로 동일 평가 과제별 실행 상한의 비교를 보고하여, 기억 효과와 추가 계산량 배분을 구분한다. 어느 쪽이 유리한지 결과를 보기 전에 정하지 않는다.

비용은 `경험 실행 + 추출 + 검증 + 통합 + 인덱싱 + 검색/원문 확장 + 평가 실행 + 수정/유지`를 모두 기록한다. 모델 입력·캐시입력·출력·추론 토큰과 호출비용, CPU/GPU 시간, 벽시계 시간을 분리한다. 총 금액 하나로 비교할 때에는 미리 정한 동일 단가표를 사용하고, 로컬 계산이나 인력을 무료라고 숨기지 않는다. 달러 절감이 추가 CPU 시간으로 바뀌는 경우도 함께 보여준다.

**해석하기 쉬운 보조 지표:** 같은 품질 이상을 유지하면서 초기 경험 비용까지 회수하는 최초의 새 과제 수 `K*`. 고정된 과제 순서와 사전에 정한 순서 재배열 분석에서 누적 전체 비용을 비교한다. 8개 안에서 회수하지 못하면 `K* > 8 또는 관측되지 않음`으로 보고하고 100개·1000개로 외삽하지 않는다. 이미 필요한 이전 연구를 재사용하는 경우의 한계비용과, 전이를 위해 경험을 새로 구매하는 경우의 전체비용을 별도로 보여준다.

**전이와 암기의 분리:** 데이터셋/원본 단위 분할, target 시작 시 기억 초기화, 저장 기술에서 데이터·예측·과제 이름 제거, 근접 과제와 작동 조건이 바뀐 과제의 분리 보고를 사용한다. 과거에 잘된 모델 이름만 복사하는 선택은 새 조건에서 실패할 수 있어야 한다. 낮은 유사성의 과제에서 이득이 사라졌다면 “근접 과제 재사용”으로 결론을 제한한다. 조건 변화는 사전에 자연스럽게 다른 데이터 특징으로 정의하며, 단순히 데이터 이름을 바꾼 복제본은 사용하지 않는다.

**반증 문장:** C가 보지 않은 과제에서 B와 강한 A를 전체비용 기준으로 이기지 못하거나, 이득이 같은 답을 재사용할 수 있는 근접 과제에만 남으면 “자기 연구 경험에서 학습한 절차가 새 연구를 개선한다”는 중심 가설을 기각한다. 빈 기억을 가진 약한 에이전트보다 좋다는 결과만으로는 채택하지 않는다. 나중에 통합을 추가하더라도, 통합 전보다 비용만 늘면 통합 기능을 기각한다.

## 6. 비용 위험과 실제 데모

가장 큰 위험은 60개의 실행 자체보다 **경험을 제대로 만들고 평가할 비용**이다. 기술 승격을 검증하려면 추가 실행이 필요하고, 과제 수가 작으면 초기 투자를 회수하기 어렵다. source 과제와 target 과제의 공통점이 적으면 압축할 반복 자체가 없어질 수 있다. SkillZip의 낮은 반복 조건에서도 압축비가 1.18×에 그친다(Table 7, LF 2804–2810). 이 경우 통합하지 않는 절차나 고정 연구자가 정답일 수 있다.

둘째 위험은 ML 공통 코드를 재사용한 효과를 연구 판단 개선으로 오인하는 것이다. 실행 시간 절약뿐 아니라 어떤 비교 실험을 생략/선택했는지, 제한된 횟수 안에서 최종 성능을 달성했는지를 보여야 한다. 셋째 위험은 기억 팽창이다. 활성 프롬프트, 저장 기술, 원시 로그·코드·검증 영수증의 전체 크기를 각각 기록한다. 활성 기술만 작아졌다면 전체 기억이 작아졌다고 쓰지 않는다.

**의미 있는 데모:** 사전 고정한 새 데이터셋 하나를 동일한 초기 상태에서 실행한다. 화면에는 연구 목표, 다음 실험, 선택 이유에 연결된 실제 이전 결과, 수행한 실험 수, 누적 전체비용, 독립 재실행 결과를 나란히 보여준다. 적용 조건이 다른 두 번째 데이터에서는 예전 기술을 버리고 새 비교를 선택하는 모습도 보여준다. 결과가 반대면 고정 절차가 더 좋았다는 결과를 그대로 보여준다. 미리 만든 매크로 이름이나 그래프 애니메이션은 성공 증거가 아니다.

논문은 이 전이·비용 실험으로 선택한 설계와 측정 한계를 보고한다. 이후 명시적으로 재개가 허용되면, 실제로 이긴 방법만 ARGO의 기존 지속 세션·도구 실행·경험 관리에 옮겨 자율 R&D 프로토타입으로 연결한다. 현재 네이티브 구현은 하지 않는다.

## 7. 후보 판정

직관성은 높고 ARGO의 반복 연구 목적과 직접 연결된다. 그러나 과학 기술 라이브러리·경험 학습과의 선행연구 충돌 위험이 높으며, 작은 공개 ML 실험이 다룰 수 있는 것은 제한된 실험 전략 전이이다. **조건부 유력 후보:** root의 가까운 선행연구 확인에서 “미노출 과제 + 강한 고정 절차 + 경험 획득을 포함한 비용”의 결합에 남는 실험 공백이 확인되고, 개발 실측에서 초기비용이 감당될 때만 최종 선택한다.
