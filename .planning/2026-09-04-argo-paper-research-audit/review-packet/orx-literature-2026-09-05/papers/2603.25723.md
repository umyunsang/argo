This report provides a detailed analysis of the research paper "Natural-Language Agent Harnesses" by Pan et al., focusing on its contributions to the field of language-model agent development.

---

### 1. Authors and Institution(s)

The authors of this research paper are:
*   Linyue Pan, Shuo Guo, Jingchen Ni, and Hai-Tao Zheng (corresponding author), affiliated with the Shenzhen International Graduate School, Tsinghua University.
*   Lexiao Zou, affiliated with Harbin Institute of Technology (Shenzhen).

### 2. How This Work Fits into the Broader Research Landscape

Modern language-model (LLM) agents are increasingly recognized as multi-step execution systems capable of complex behaviors such as tool use, state maintenance, failure recovery, intermediate result validation, and task delegation. These functionalities are orchestrated by an external component referred to as a "harness," which significantly influences the agent's performance. The concept of agent scaffolds, workflow generation, long-context execution, multi-agent orchestration, and tool-using agents are related areas that underscore the importance of these external control mechanisms.

A prevalent issue in current agent development is that these harnesses are typically implemented as tightly coupled bundles of code. This code often intermixes prompts, tool adapters, parsing rules, validation scripts, artifact paths, retry logic, and context management policies. This tight coupling renders harnesses difficult to inspect, compare, transfer, and systematically ablate, impeding a clear understanding of their underlying design patterns and effects on agent behavior. Consequently, harnesses are often not treated as distinct, analyzable research objects.

This work addresses this challenge by proposing a method to externalize the harness pattern as an executable natural-language object. It distinguishes itself from prior work on natural-language instruction carriers (e.g., `AGENTS.md` for simple tool descriptions) and natural language as programs or workflows (e.g., prompt programming frameworks) by focusing on the run-level harness policy. Instead of merely instructing individual model calls or defining fixed pipelines, this research aims to represent the entire lifecycle of an agent's task run in an editable natural-language format, thereby allowing the strategic aspects of agent control to be more transparent and amenable to scientific inquiry. The paper's contribution lies in introducing a framework that separates harness *policy* (expressed in natural language) from *mechanisms* (executed by a runtime and deterministic code), thereby attempting to transform harnesses into explicit, auditable, and modifiable entities.

### 3. Key Objectives and Motivation

The primary objective of this research is to investigate whether the reusable design pattern of an agent harness can be externalized and represented as an executable natural-language object. This central question is motivated by the observation that while the external harness profoundly shapes an agent's performance, its implementation is typically embedded within complex, tightly coupled controller code. This entanglement makes harnesses challenging to inspect, compare, transfer across different systems, and systematically analyze through ablation studies. The opaque nature of these code-based harnesses hinders the advancement of agent design by obscuring the policy choices that drive agent behavior.

To address this motivation, the authors introduce two main components:
1.  **Natural-Language Agent Harnesses (NLAHs)**: These are editable documents designed to describe the run-level policy of a harness using natural language. The intent is for NLAHs to explicitly state how an agent run should be organized, including its stages, roles, state management rules, verification conditions, recovery procedures, and stopping criteria.
2.  **Intelligent Harness Runtime (IHR)**: This is a shared execution environment engineered to interpret the natural-language policies defined in NLAHs. IHR translates these policies into concrete agent operations such as initiating agent calls, managing handoffs between agents, updating execution state, enforcing validation gates, and establishing artifact contracts.

The research subsequently evaluates this core proposal through three specific research questions:
*   **RQ1 (Harness Realization)**: Can NLAHs, when executed by IHR, effectively control real agent runs and maintain task performance comparable to traditional code-based harnesses and simpler prompted realizations (where NLAH text is used as a passive instruction)? This question assesses the operational viability and expressiveness of NLAHs as a control mechanism.
*   **RQ2 (Harness Mechanism Realization)**: Do IHR-executed NLAHs genuinely materialize the intended harness mechanisms (such as workflow structure, contract enforcement, tool use, recovery, and information handoff) beyond merely mimicking the behavioral traces of ordinary prompting? This question examines whether the IHR provides stronger, more explicit execution semantics for the natural-language policy.
*   **RQ3 (Module Ablation)**: Once harness policies are explicitly defined in natural language, can individual modules within an NLAH (e.g., file-backed state, verifier separation, self-evolution, multi-candidate search) be cleanly isolated, ablated, and analyzed to determine their specific impact on task outcomes and process metrics? This question explores the analyzability and modularity benefits of the NLAH approach.

The overarching motivation is to transform agent harnesses from being incidental, opaque glue code around LLMs into explicit, inspectable, and scientifically analyzable representation objects, thereby facilitating systematic research and improvement in agent design.

### 4. Methodology and Approach

The methodology centers on a distinct separation of concerns: natural language is utilized for carrying high-level harness policy, while code and a dedicated runtime handle the exact mechanisms of execution.

**NLAH+IHR System Architecture:**
The proposed system comprises four conceptual layers:
1.  **Base Agent**: This foundational layer is a minimal, executable substrate, primarily an LLM loop. It possesses the capability to call an underlying language model and interact with the external environment via a terminal. Through this terminal, it can perform operations such as reading and writing files, executing processes, logging events, and launching child agents. The ability to launch child agents is achieved via the terminal, passing a child task packet to a new instance of itself.
2.  **Runtime Policy**: This is a fixed, text-form instruction provided to the base agent. Its purpose is to define how the base agent should interpret and execute the subsequent natural-language harness documents, thereby transforming the base agent into the Intelligent Harness Runtime (IHR). This policy establishes shared execution semantics, including parent-child boundaries, the meaning of an agent call, artifact and state handling, completion gates, and audit requirements.
3.  **Natural-Language Agent Harness (NLAH)**: This layer consists of editable natural-language documents that embody the specific policy for a given task run. NLAHs describe aspects such as the stages of a task, agent roles, rules for state management, verification conditions, recovery strategies, and stopping criteria. The NLAH defines *what* the run should achieve and *when* certain mechanisms should be invoked, rather than specifying low-level operations.
4.  **Scripts and Adapters**: These are deterministic code components responsible for precise, unambiguous operations. Examples include running tests, parsing results, interacting with benchmark-specific tools, or validating artifacts. They function as hooks executed by agents through the filesystem via bash.

**Intelligent Harness Runtime (IHR) Design:**
IHR is designed as a thin, shared runtime. It leverages the base agent as an orchestrator, guided by the runtime policy. It delegates substantive task work to child agents, even for nominally single-agent harnesses, ensuring a visible boundary between harness control and task execution. For multi-role or multi-branch harnesses, IHR launches separate child agents, providing each with a specific task packet, supervising handoffs, and recording behavior. This design allows IHR to provide a common execution substrate for natural-language harness policies.

**Principles for Writing NLAHs:**
The authors identify several principles for crafting effective NLAHs:
*   **Task Contract**: Clearly define inputs, expected outputs, allowed tools/artifacts, and completion conditions at the outset.
*   **Stage-Mechanism Separation**: Name stages (e.g., inspect, plan, edit, verify), but delegate low-level tool operations to scripts, defining *when* mechanisms are used and *what evidence* they produce.
*   **Explicit State and Evidence**: Specify where state is stored, which artifacts are crucial for subsequent agents, what evidence supports claims, and which files or logs signal task completion.
*   **Ablatable Modules**: Design NLAH sections with clear names for modules (e.g., verifier, self-evolution) to facilitate their removal or modification for analysis.
*   **Simple, Enforceable Language**: Use concise clauses, concrete conditions, and explicit artifacts to ensure IHR can interpret and execute policies consistently.

**Experimental Design:**
The evaluation addresses the three research questions by comparing different harness realizations across three benchmark families.

**Harness Realizations for RQ1:**
1.  **Code Harness**: The original code implementation of the agent harness family, representing the strongest and most deterministic control, albeit with policy intertwined with implementation details.
2.  **Prompted NLAH**: The NLAH content provided as standard prompt instructions to a Codex CLI agent, without the specific execution semantics of IHR. This assesses natural language as a passive instruction carrier.
3.  **IHR-executed NLAH**: The NLAH interpreted and executed by the IHR, benefiting from its explicit runtime semantics for child lifecycle, artifact/state handling, contract gates, and stopping conditions.

**Benchmarks:**
The evaluation employed three benchmark families known for requiring multi-step control, tool use, durable state, and verification:
*   **Coding**: SWE-bench Verified, using the Live-SWE-Agent harness family.
*   **Terminal-use**: Terminal-Bench 2.0 (TB2), using the MHTBA harness family derived from Meta-Harness.
*   **Computer-use**: OSWorld, using a SeeAct-style GUI harness family.

**Experimental Setup:**
All experiments used Codex CLI version 0.123.0 with the `gpt-5.4-mini` model (reasoning effort `xhigh`). Runs were executed in Docker containers on Ubuntu 24.04 servers, with resource caps per task (32 vCPUs, 84 GiB memory, 40 GiB storage) to ensure reproducibility and safety.

**Metrics:**
*   **RQ1**: Primary benchmark metrics (e.g., issue resolution rate, task success), LLM calls, tool calls, prompt/completion tokens, and run time.
*   **RQ2**: Metrics for workflow structure preservation (e.g., Prompt Contract, Workflow Preservation, Stage Coverage), as well as specific mechanism instantiations (e.g., Artifact Contract, Tool Call Success, Information Handoff Recall).
*   **RQ3**: Task performance and 'Agent Calls' (indicating execution topology changes) for various ablated modules to assess their impact.

### 5. Main Findings and Results

The study evaluated Natural-Language Agent Harnesses (NLAHs) and the Intelligent Harness Runtime (IHR) across three research questions, yielding findings regarding their operational viability, mechanism realization, and modularity.

#### 5.1 RQ1: Harness Realization

The first research question investigated whether IHR-executed NLAHs could control agent runs while maintaining task performance comparable to code-based and prompted realizations.

*   **Operational Viability**: IHR-executed NLAHs demonstrated competitive task performance across the evaluated benchmarks.
    *   On **Live-SWE**, IHR-executed NLAH achieved a 73.0% resolution rate, which was above the native code harness (67.0%) and close to the prompted NLAH (77.0%).
    *   On **OSWorld**, NLAH reached 46.3%, closely matching the code harness at 47.1%.
    *   On **MHTBA**, NLAH obtained 53.9%, which was below the prompted version (57.3%) but significantly higher than the native code realization (36.0%). The lower performance of the MHTBA code artifact under the GPT model was attributed to cross-model portability issues, as its original optimization was for Claude Opus 4.6, leading to brittle stopping protocols with GPT.
*   **Cost Profile**: IHR-executed NLAHs generally incurred higher costs in terms of model calls, tool calls, or tokens compared to code harnesses. This was attributed to the overhead of the prototype runtime, which relies on a general agent substrate and natural-language orchestration. However, this increased cost did not negate task performance, and in some cases (e.g., Live-SWE), the added autonomy led to faster wall-clock times.
*   **Conciseness of Policy Layer**: NLAHs substantially reduced the static material required to represent the harness policy. For Live-SWE, the readable harness policy was condensed from 60.1k tokens of code to a 2.9k-token NLAH. For MHTBA, it reduced from 10.5k to 0.8k tokens. This transformation exposes the high-level policy, such as state handling, validation, recovery, and completion gates, in a directly inspectable format.
*   **Policy-Guided Flexibility**: NLAH execution demonstrated flexibility in achieving task goals. For instance, in OSWorld tasks, the NLAH preserved staged observation and action selection but allowed for diverse concrete routes (e.g., GUI tasks completed via shell commands) to satisfy the same completion contract, reflecting the benefit of expressing policy at a goal-oriented level.

#### 5.2 RQ2: Harness Mechanism Realization

The second research question explored whether IHR-executed NLAHs materialized intended harness mechanisms beyond merely using text as passive instructions.

*   **Workflow Structure Preservation**: NLAH runs exhibited recognizable workflow structures, reflected in non-trivial scores for prompt-contract, tool-surface, workflow-preservation, stage-coverage, and ordered-workflow metrics. On Live-SWE, NLAH improved Verification Signals (9.890), Stage Coverage, and Ordered Workflow compared to prompted execution. On MHTBA, NLAH maintained similar Workflow Preservation, slightly higher Stage Coverage and Ordered Workflow, but lower Context Boundary and Model Match due to the distributed nature of parent-child execution.
*   **Strong Mechanism Instantiation**: High compliance rates were observed for artifact contracts (1.000 on Live-SWE, 0.955 on MHTBA), tool call success (0.933 on Live-SWE, 0.928 on MHTBA), and continuation after failed tool calls (0.992 on Live-SWE, 0.995 on MHTBA). These metrics indicate that IHR effectively translated natural-language instructions into observable artifacts, tool-mediated execution, and recovery behaviors.
*   **Mechanism Weakness: Handoff**: A notable limitation was identified in handoff mechanisms. NLAH's Orchestration Reliability was lower than Prompted NLAH on both Live-SWE and MHTBA. Information Handoff Recall significantly decreased in parent-child execution for NLAH (0.322 on Live-SWE, 0.553 on MHTBA) compared to direct-context prompting. This suggests that while mechanisms are materialized, the prototype runtime introduces information loss across execution boundaries.

#### 5.3 RQ3: Module Ablation

The third research question investigated whether explicit NLAH modules could support meaningful intervention and analysis under a shared runtime.

*   **Effective Modules for State and Acceptance Discipline**:
    *   **File-backed state** improved performance on both SWE-bench (73.0 to 75.6) and OSWorld (44.4 to 58.3).
    *   **Self-evolution** demonstrated substantial gains on SWE-bench (73.0 to 78.8) and OSWorld (44.4 to 52.8).
    *   **Evidence-backed answering** consistently provided modest positive gains (+2.8 on both benchmarks).
    *   These findings suggest that modules enhancing state preservation, enforcing explicit evidence requirements, or refining retry decisions are most beneficial by clarifying the path to task acceptance.
*   **Branching Complexity vs. Control Effectiveness**:
    *   **Multi-candidate search** significantly increased 'Agent Calls' (from 1.1 to 5.7 on SWE-bench and 1.083 to 1.333 on OSWorld), indicating greater execution branching. However, this complexity resulted in a modest gain on OSWorld (+2.8) and a slight performance drop on SWE-bench (73.0 to 71.4). This indicates that increased search or branching is not inherently beneficial and can be costly without alignment with benchmark acceptance criteria.
*   **Context Management Effectiveness**:
    *   **Context compression** generally showed negative effects on both benchmarks (SWE: -1.0; OSWorld: -8.3).
    *   **Markdown memory** had mixed results, negatively affecting SWE-bench (-2.8) but positively impacting OSWorld (+5.6).
    *   In contrast, **file-backed state** consistently delivered positive results, suggesting that path-addressable durable state is a more reliable and robust information carrier than aggressive summarization or free-form memory notes, particularly when evaluation depends on action-critical details.

Overall, RQ3 concluded that explicit NLAH modules are valuable when they directly contribute to shortening the path from intermediate work to auditable evidence and final benchmark acceptance. Conversely, modules that primarily add local process layers, extra branching, or compressed summaries whose success metrics can diverge from the evaluator's criteria tend to be less effective.

### 6. Significance and Potential Impact

This research introduces a paradigm shift in how agent harnesses are designed, analyzed, and managed, moving them from opaque, embedded code to explicit, natural-language-based representations.

**1. Enhanced Inspectability and Comparability:** By externalizing harness policy into Natural-Language Agent Harnesses (NLAHs), the study makes the strategic components of agent control directly readable and editable. This transparency allows researchers and developers to inspect, understand, and compare different harness designs more easily than when policies are intermingled with low-level implementation details in code. This contributes to a more systematic understanding of what constitutes an effective agent harness.

**2. Facilitated Transferability and Ablation Studies:** The IHR-executed NLAH framework enables the transfer of harness policies across different agent systems or tasks with reduced effort. Furthermore, the modular nature of NLAHs, as demonstrated by the ablation studies, allows for controlled experimentation. Researchers can isolate and modify individual policy modules (e.g., state management, verification, recovery strategies) to quantitatively assess their impact on agent behavior and task outcomes. This capability transforms harness design into an amenable subject for scientific experimentation, moving beyond ad-hoc engineering.

**3. Reframing Harnesses as Scientific Objects:** The work argues for treating agent harnesses as "scientific representation objects" rather than incidental glue code. This perspective encourages rigorous study into which harness policy choices lead to superior agent performance and how those choices interact. The framework provides a common substrate (IHR) under which various natural-language policies can be executed and audited, fostering a more principled approach to agent development.

**4. Clear Division of Labor:** The research reinforces a pragmatic division between natural language and code in agent systems. Natural language is identified as well-suited for expressing high-level, human-interpretable policy (e.g., roles, contracts, evidence requirements, recovery rules). In contrast, deterministic code is retained for precise, reproducible, and safety-critical mechanisms (e.g., tool execution, sandboxing, parsing, evaluation). This division avoids over-claiming the capabilities of natural language while leveraging its strengths for flexible policy definition.

**5. Future Research Trajectories:** The establishment of explicit harness representations opens new avenues for research. Future work could explore methods for retrieving, composing, mutating, and optimizing NLAH modules automatically under shared runtime assumptions. This could lead to a "controlled science of harness representations," where the focus shifts from comparing entire agent systems to analyzing the specific harness policy choices that drive performance differences.

**Potential Risks and Limitations:**
The study acknowledges inherent limitations, primarily the imprecision of natural language, which can lead to misinterpretation or semantic ambiguity across different models. This necessitates keeping exact mechanisms in code and relying on execution audits rather than inference from text alone. Broader impacts include the potential for portable harness logic to lower the barrier for spreading risky workflows; thus, deployment would require robust safeguards such as provenance tracking, review processes, permission control, and sandboxing to mitigate risks like prompt injection or malicious tool grafting.
