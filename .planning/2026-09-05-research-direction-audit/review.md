# 자율 연구 방향 검토

작성일: 2026-09-05 KST. 내부 검토용이며 졸업논문 본문이 아니다.
상태: 내부 방향 검토. 실험·제품 구축·논문 수정·제출을 승인하지 않는다. 현재 source snapshot과 선택해 읽은 문헌 범위에 한정한 판정이며 전 문헌 조사나 SOTA 인증이 아니다.

## 1. 결론

**연구 방향은 타당한 방향으로 좁혀졌지만, 현재 증거로 최신 최상위 연구 시스템이나 최적 설계라고 판정할 수 없다.** 중요한 개선은 기능을 많이 조합하는 것에서 벗어나, 같은 자원에서 두 의사결정 정책을 비교하는 질문으로 이동했다는 점이다. 반면 지금 실행하는 합성 구조 과제와 최종적으로 입증하려는 실제 연구 설계·실험 선택·세션 인계 능력 사이에는 아직 검증해야 할 간격이 있다.

최종 목적은 재료들을 모두 채택하는 것이 아니라, **어떤 최소한의 정책이 어떤 연구 상황에서 비용 대비 이득을 주고, 어느 상황에서는 단순한 대안보다 못한지 결정하는 것**이어야 한다. 그래프 저장소, 검색 서비스, 에이전트 숫자 또는 반복 횟수 자체가 공헌은 아니다.

| 관찰 | 지금 허용되는 해석 | 허용되지 않는 해석 |
|---|---|---|
| Stage0의 96 체크와 16개 fixture | 평가기·경계·재현 조건에 대한 도구 검증 | 96번의 자율 연구 성공 |
| 초기 파일럿과 B2의 후속 교정 | 측정·조작 정의를 개선한 개발 과정 | 교정 전 결과를 선택해 효능으로 인용 |
| B3의 8 episodes, 4개 구조 family | 별도의 C 계획으로 넘어갈 개발 신호 | 독립 과학 도메인 4개 또는 모집단 효과 입증 |
| C64의 16 tasks × 2 conditions × 2 blocks | 첫 32 episodes의 주 분석과 역순 32 episodes의 신뢰도 반복 | 독립 표본 32개/64개 또는 이미 완료된 효능 결과 |
| 기존 daemon/REPL/RLM과 관련 소스 | 계승하는 구현 기반과 소유권 | 새로 입증한 과학적 성능 |

검토 중 외부 세션 상태가 바뀌었다. 12:17:34 KST에 `argo-paper-root`는 사용자 메시지 “C 실행 승인”을 받았다. 세션 소유자는 사전 권고에 따라 C64를 선택하고 12:18:30에 정확히 64 attempted episodes의 승인 영수증을 남겼다. 사용자가 “C64”를 직접 선택했다고 바꾸어 인용하지 않는다. 12:20:32에 실행 시작이 보고되었고 PID 및 진행 영수증을 확인했다. **이 검토자가 시작한 실험은 없다.**

12:28:58 KST에 확인한 진행 영수증은 64개 중 14개의 기록이었다. 이는 시점별 진행량일 뿐이며 효과의 중간 판정은 하지 않는다. 처음 한 쌍의 결과가 상태 조회 중 노출되었으므로 이 검토는 블라인드 사전등록이 아니다. 실행 중 설계·채점·예산·중단 기준을 바꾸지 않는다. 이후 조회는 결과값을 제외한 상태·식별자·개수로 제한한다.

근거: `evidence/authority-hashes-at-synthesis.json`, `evidence/concurrent-confirmation-progress.json`, 보존된 승인/설계 snapshot. 사전 실행 명령 문자열 오류(exit 127)는 모델 episode 시작 전의 운영 실패로 별도 기록되어 있으며 과학 결과가 아니다.

## 3. 유지할 설계 선택

1. **단일 핵심 대비를 유지한다.** 동일 기회·자원의 결과 기반 실험 트리와 typed evidence-dependency/version 정책을 비교한다. 과거 G×C×F 8조건은 현재 의무 설계가 아니며 다시 강제하지 않는다.
2. **런타임 기반을 고정한다.** 같은 모델·도구·자료·run owner·후보 공간에서 정책만 바꾸어야 한다. 정책 구현이 달라지므로 전체 코드 hash가 같아야 한다는 요구 대신, 공통 기반 hash와 각 정책 hash를 각각 고정한다.
3. **실패와 제한을 결과의 일부로 유지한다.** 오류·시간 초과·부적합 산출물을 성공에서 제외하고 숨기는 방식은 금지한다. 원래 시도와 허용된 기반시설 재시도를 구별한다.
4. **개발·확인·제품 입증을 분리한다.** C의 긍정 결과가 나와도 실제 연구 workflow와 native 구현까지 자동 승격하지 않는다. 부정·불확실 결과 역시 그 측정 범위를 넘어 해석하지 않는다.

## 4. 보수적 가설과 다음 의사결정

현재 C의 가설과 채점 규칙은 이미 고정되었다. 아래 항목은 그것을 대체하는 실행 지시가 아니라, 완료 후 해석과 별도 승인받을 후속 설계의 의사결정 기준이다.

| 설계 결정 | 근거와 선택 이유 | 반증 또는 대안 | 아직 필요한 관문 |
|---|---|---|---|
| C는 제한된 근거 할당의 기전 실험으로 해석 | 구조와 record budget이 통제되어 작은 원인 대비를 보기 좋음 | 실제 실험 선택을 하지 않으면 전체 연구 능력의 대리척도로 승격할 수 없음 | 동결된 결과·실패·원시 기록에 의한 완료 판정 |
| 강한 비그래프 정책을 다음 비교의 기준으로 사용 | 단순한 약한 대조군보다 잘하는 것으로는 graph-native 필요성을 설명할 수 없음 | 같은 관계 정보와 효율적인 탐색을 쓰는 결과 트리/단순 dependency cache | 구현·기회·예산 대등성 확인과 별도 실행 승인 |
| 필요한 경우에만 근거 할당 기전을 분리 | 좋은 첫 record 제공의 이득과 지속적 graph control의 이득은 다름 | 양쪽에 같은 첫 record를 주는 사전 계획된 진단 비교 | C를 변경하지 않는 별도 진단 설계와 승인 |
| 실제 R&D 연결 과제를 후속 외적 타당도 대상으로 설정 | 구조 다양성만으로 도메인 정합성이 생기지 않음 | 주장: 다음 실험 선택·선택적 재검증·fresh-context handoff를 실제 관찰 가능 과제로 바꾸지 못하면 workflow 주장을 보류 | 데이터/도메인 계약·독립 채점·새 과제 승인 |
| 긍정 결과보다 더 단순한 구현이 가능한지 먼저 비교 | 그래프 구축·조회·정정·복구 비용까지 포함해야 효용을 판단 가능 | 효과가 작거나 단순 대안과 동등하면 graph는 감사·출처 용도로만 유지 | 사전 정의된 유용성 기준과 총비용 기록 |

권고하는 후속 연구 질문은 “정해진 연구 문제에서 근거의 정정·철회·범위 변경이 발생했을 때, typed 정책이 강한 결과 기반 정책보다 **정답인 다음 행동과 필요한 결정의 재검증을 더 잘 선택하고, 무관한 결정을 불필요하게 재개하지 않는가**”이다. 정답 행동은 gold 계약으로 독립 정의해야 하며 LLM 평점만으로 정의하지 않는다. 문장 품질이나 인용 수는 이 질문의 주 평가변수가 아니다.

## 5. 통계 해석의 경계

- C의 독립 단위는 16개의 구조 과제다. C64의 추가 block은 동일 과제의 순서 반전 신뢰도 반복이지 새로운 n이 아니다. 주 분석과 반복을 따로 보고하고 더 좋은 block만 선택하지 않는다.
- 동결 문서는 two-sided exact sign test를 명시한다. 다른 검정이나 one-sided p값으로 실행 후 바꾸지 않는다. H0 문구 및 검정 방향에 불일치가 있다면 원본을 보존한 채 해석 주석으로 드러낸다.
- 큰 승률·discordance 가정에서 나온 표본수는 그 가정에서의 계산일 뿐, 현재 연구의 실제 검정력 보증이 아니다. B3의 작은 결과를 “보수적”이라는 말로 확인 과제의 분포로 이전하지 않는다.
- 별도 산술 대조에서 n=16의 가정별 양측 기각확률은 (discordance 0.75, 승률 0.90)에서 81.2%, (0.50, 0.90)에서 53.9%, (0.50, 0.75)에서 17.4%였다. 계산 오류가 아니라 가정 민감도가 핵심이며, 이 값은 위해·비용 조건까지 만족하는 전체 성공확률이 아니다. 실행 중 표본수는 변경하지 않는다.
- 영향 있음/없음 각 8개에서 관측된 위해가 0이어도 일반적인 안전성 입증은 아니다. “이 표본에서 관측 없음”으로 표현한다.
- 비유의 결과는 효과 없음/동등성 입증이 아니다. 과제 표집 방식, 신뢰구간·불확실성과 실질적으로 유용한 효과의 배제 여부를 함께 판단한다. 실행 후 효과 기준을 낮추지 않는다.

정적 코드 검토에서는 missing/malformed 산출물·scorer 예외가 완전한 실패 포함 receipt/분모를 남기지 못할 수 있고, 저장된 exit/timeout 상태를 현재 점수 집계가 사용하지 않는 경계도 확인했다. 실제 C에서 그런 실패가 관찰됐다는 주장은 아니다. 종료 뒤 원래 시도·실패를 모두 설명하지 못하면 해당 acceptance를 보류해야 하며, 실행 중 코드 수정이나 조용한 재시도는 금지한다.

세부 검토와 산술 근거는 `experiment-review-root.md`에 있다. 통계 담당 branch는 연결 중단으로 최종 보고서를 받지 못해 종료했고, 이 항목은 root가 원본/동결 snapshot을 직접 대조한 검토다. 독립 통계 재검토 완료로 포장하지 않는다.

## 6. 재료를 연결하는 원칙

| 재료 | 내부 설계에서의 위치 | 과학적으로 평가할 부분 |
|---|---|---|
| pi / Prime Agent | 계승하는 daemon·AgentSession·worker·REPL/RLM 및 복구 기반 | 고정 기반 위의 정책 차이; 재포장한 기능을 독창성으로 주장하지 않음 |
| OpenResearch CLI | 과학 실행과 receipt의 단일 소유자 | 프로토콜·run·원시 결과의 일관성; 중복 실행 권한을 만들지 않음 |
| Exa | 후보 문헌을 찾는 discovery adapter | 필요할 때만 retrieval budget과 근거 채택 정확도를 비교; 검색 결과 자체는 검증된 근거가 아님 |
| Context graph | 출처 bytes/span → 주장 → 대안 → 결정 → 실행 → 결과의 versioned projection | 선택적 영향 전파와 fresh-context 소비의 정확성; JSON 구조 검사와 실제 소비 검증을 구별 |
| Loop engineering | 고정된 연구 정책의 제한된 재검증·반증 루프 | 실패를 발견하고 중단/수정하는 유용성; 반복 횟수 자체는 보장 아님 |
| Graph engineering | 관계·범위·버전·무효화 규칙의 명시적 구현 | 복잡한 graph가 단순한 cache/로그/트리보다 필요한 조건 |

제품 후보를 먼저 모두 넣고 그 결합을 논문으로 정당화하지 않는다. 문헌에서 가져오는 것은 검증 가능한 메커니즘과 비교 규칙이며, 어떤 제품을 쓰는지가 과학적 근거를 대신하지 않는다. 구체적인 ownership/인계 검토는 `architecture-review.md`에 둔다.

### 관찰된 인계 불일치와 구현 한계

- 12:26:59 KST의 active handoff가 지정한 ROOT hash는 `2c4647d9e8c47262a4261fa27be1a2278dd540c7a4482b4d56dde472ffe4f97e`이지만, 실제 ROOT hash는 `4d972add03586e67ea39bd8492bade238cc6f68b8c85bcb00408081b67637419`였다. 12:35:49에도 재확인했다. 이는 새 에이전트가 다른 revision을 혼합할 수 있는 **snapshot 일관성 문제**다. 후속 confirmation 블록의 별도 C64 승인은 존재하므로 무승인 실행이라고 해석하지 않는다.
- 일부 active-document 편의 필드는 B2 승인 대기 상태를 가리키지만 후속 C64 승인 블록은 갱신되었다. 실행 중 파일을 고치는 대신, 종료 뒤 별도 admission에서 ROOT·승인·설계·결과·제외 이유를 한 revision으로 묶는 비순환 immutable capsule을 제안한다. JSON/hash 검사만으로 실제 fresh-context 소비가 맞았다고 판정하지 않는다. 해당 소비 acceptance는 아직 `NOT_RUN`이다.
- 현재 C runner는 직접 CLI를 부르는 Python 검증 실행기다. 이 실행이 통합 과학 run owner나 native 연구 엔진의 구현 완료를 뜻하지 않는다. daemon 세션, 과학적 run receipt, 그래프 projection의 소유권을 혼합하지 않는다.
- runner의 같은 output/attempt 경로 재실행은 기존 디렉터리를 제거할 수 있다. **실제 덮어쓰기나 자료 손실을 관찰한 것은 아니다.** 이번에 재실행을 허용하지 않으며, 이후 별도 구현에서는 고유 attempt ID와 no-clobber 정책을 검토한다. 승인 직전 코드 hash 대조도 정책/공통 기반 fingerprint와 구별해 명시할 필요가 있으나, 현재 runner의 승인 이후 drift가 관찰됐다는 뜻은 아니다.

## 7. 선행연구의 적용

`literature-review.md`의 실제 읽기 범위와 primary-source locator를 기준으로 반영한다. 최신 preprint라는 이유만으로 검증된 최상위 방법으로 승격하지 않으며, 논문이 보고한 결과와 이 프로젝트의 결과를 섞지 않는다. 단일 예쁜 점수 대신 같은 과제·예산·모델·도구·반복·실패 분모를 맞춘 비교 가능성을 우선한다.

| 실제 선행연구 | 이 설계에 적용할 통찰 | 잘못 가져오면 안 되는 주장 |
|---|---|---|

`literature-review.md`에 7편의 정확한 식별자·버전·URL·읽은 절과 한계를 기록했다. 5편은 실질적인 선택 절을 읽었고, ScienceAgentBench는 제한된 분석 절, POPPER는 식별/초록 수준이다. **완독한 7편이라고 보고하지 않는다.** 신규성 압력과 비교 설계의 근거로만 사용하며, 여기의 미검증 주장을 논문에 자동 반영하지 않는다.

종합하면 비교를 늘리는 대신 **강한 tree 한 개 → 필요한 경우에만 version-aware log/vector 한 개 → 실제 workflow 전이 한 가지**로 좁히는 것이 낫다. 이 순서는 실행 계획 승인이 아니라, 현재 연구가 과도한 주장 없이 실패할 수 있도록 만드는 후속 제안의 우선순위다. 단순한 대안이 같은 효용을 더 낮은 비용으로 달성하면 그 대안을 채택하는 결과도 연구 성공이다.

## 8. 다른 에이전트를 위한 그래프

`proposed-context-map.json`은 이 검토의 근거·판단·대안·반증·제한을 기계적으로 읽기 위한 **DRAFT_NOT_APPLIED** overlay다. `paper/context-graph.json`을 대체하거나 덮어쓰지 않는다. `context-map.svg`는 같은 검토 결정을 사람이 읽기 위한 요약도이며 제품 구현이나 논문 그림이 아니다.

새 에이전트의 소비 순서는 현재 ROOT → active handoff manifest → 그 manifest가 지목하는 승인/설계/receipt hash → 이 audit snapshot 비교다. 과거 overlay나 논문 편집용 graph를 현재 실행 권한으로 사용하지 않는다. source hash 변경은 관련 판단의 재확인 사유이지 이 검토에 실행 권한을 부여하는 신호가 아니다.

도식은 흑백 기술 블록 구성으로 렌더링해 텍스트 잘림 없이 확인했다. 이는 도식의 가독성 확인일 뿐이며, 실제 에이전트의 graph 소비 acceptance나 실험 효능 검증은 아니다.

## 9. 졸업논문과 해커톤의 분리

- 논문은 확인한 학술 근거와 검증 범위만 담는다. ARGO/NAIS 및 내부 제품·서비스·CLI 이름, 향후 해커톤 로드맵은 본문에 들어가지 않는다. 현재 1단 Quarto 판본을 이 검토에서 바꾸지 않는다.
- 사용자가 준 공식 모집 공고의 인쇄 p.5는 실제 개발 수행을 본선 기간에 진행하도록 요구한다. 현재 공식 사이트의 본선 전체 일정은 2026-09-30 17:00부터 2026-10-01 12:00 KST이며, 이것을 순수 개발시간으로 바꾸어 주장하지 않는다. 접수 마감은 2026-09-07이다.
- 기존 연구·오픈소스·사용자 작성 코드 재사용 허용 범위는 별도 확인 사항이다. 사전 프로토타입 제작을 임의로 승인하지도, 모든 사전 연구가 금지되었다고 확대 해석하지도 않는다. 운영진 문의/제출/공개는 이번 검토의 권한에 없다.
- 근거 PDF와 웹 bundle의 hash 및 선택한 페이지 텍스트는 `evidence/`에 보존한다. 이름이 비슷한 튜토리얼/다른 경진대회 일정과 혼동하지 않는다.
