## Four architecture decisions and strongest gaps

### 1. Keep three authorities distinct; implement an importer, not another orchestrator

**Decision proposed:** preserve native session execution authority; keep ORX as the designated integrated scientific-run authority; make the research graph a derived decision/evidence projection. Engine refinement has separate version/admission lineage and links to research failures without rewriting their scientific meaning.

**Evidence:** native responsibilities are explicit in L13 lines 43–47 and 64–82; existing session/goal persistence is visible in `packages/coding-agent/src/core/agent-session.ts:1043`, `:1667` (L24). The material map distinguishes future research owners from existing execution at L06 lines 23–29. The current C runner is a small direct `subprocess.run` client, not an ORX importer (L18 lines 18–29). That bounded microbenchmark implementation is real; it neither demonstrates nor contradicts an already implemented native research plane, because that plane is still proposed.

**Alternative:** a separate research daemon/run database creates competing cancellation, terminal-state and recovery authorities without establishing a research benefit. The simpler design is an idempotent import keyed by ORX project/run/attempt identity and immutable terminal receipt.

**Falsifier / unresolved implementation gate:** after separate admission, replay/import the same terminal receipt twice, recover a session, and ensure one scientific result identity with unchanged bytes; reject conflicting terminal receipts. No native import/recovery test was performed. The current C run must not be retrofitted to ORX or a new engine mid-run. Construction still requires explicit restart (`docs/argo/agent-brief.md:29`; L01).

**Decision proposed:** one externally supplied immutable capsule digest should bind ROOT, active design, material map, next action/approval revision, source/claim versions and run receipts. ### 4. Treat C as a dependency/allocation microbenchmark, not the integrated research-tree or handoff evaluation

**Evidence:** current C question concerns decision-relevant allocation across synthetic structural graphs under a two-record budget; its own claim ceiling is that task population and one model (`paper/research/confirmation-design.json:5`, `:68`; L19). The integrated design instead requires competing explanations, distinguishing predictions, next experiment, observation, successor decision and fresh-context handoff (L05 lines 63–70), with selective invalidation, nonduplicate discriminating action and chat-free allowed/forbidden-action recovery (lines 82–88). The active handoff's deterministic acceptance is still `NOT_RUN` (L07 lines 322–340). Runner readiness is meaningful engineering progress, not coverage of that entire chain. No counts, effect estimates, interim outcomes or power conclusions are supplied here.

**Decision proposed:** retain the frozen C claim ceiling. Any subsequent integrated evaluation must contrast typed/version-dependent control with a genuinely strong result-driven experiment tree that can branch, repair, improve and revise using identical observations and opportunities. Both receive the same immutable logging and source access; neither earns success merely for satisfying mandatory recording.

**Strong simpler controls:** use the same append-only evidence log/index under both main policies. A flat but result-aware indexed decision state is the low-complexity architectural alternative, not a deliberately weak generic-iteration strawman. If retrieval rather than state policy could explain a result, compare identical frozen corpus/spans with matched vector or lexical retrieval, context/token/tool budgets and candidate exposure. If edge semantics remain ambiguous, a later matched edge-label/permutation or relevant-versus-irrelevant dependency perturbation can distinguish selective control from extra context or generic caution. None is an automatically authorized factorial expansion.

**Falsifier / unresolved gate:** after separate admission, typed machinery must improve independently checkable next-experiment/handoff success or reduce invalid reuse/unnecessary repetition at a justified overhead, while preserving valid unrelated decisions. If the strong tree/index matches it, or an advantage disappears under equal retrieval/opportunity, choose the simpler tree/index plus audit export. A graph may be necessary for bookkeeping or interoperability without being scientifically superior. Complexity, an attractive graph, a working microbenchmark, and literature resemblance are not SOTA evidence.
